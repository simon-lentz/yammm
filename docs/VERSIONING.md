# yammm Versioning Policy

This document codifies yammm's versioning commitments — both API and wire-format — so consumers and contributors have one authoritative reference for what a given release bump is permitted to change. Added in v0.3.0 release prep.

## Scope

yammm's versioning covers two surfaces that evolve on related but distinct cadences:

1. **Go API surface** — exported types, functions, methods, constants, options, and their documented behavior under the `github.com/simon-lentz/yammm` module.
2. **`.ys` wire format** — the on-disk shape of snapshots produced by `snapshot.Marshal` and consumed by `snapshot.Load` / `snapshot.Info` / `snapshot.HeaderOnly` / `snapshot.Verify`. The wire format carries its own `version` field in the header (currently `4`, first tagged by v0.19.0; `3` from v0.12.0 through v0.18.0).
3. **Generated Go output (`adapter/gogen`)** — the shape of the Go source `gogen.Marshal` emits for a given schema and options. Promoted to a committed surface in v0.6.0 (the v0.5.0 notes anticipated promotion "if a downstream consumer comes to depend on that shape"; a downstream consumer now byte-pins committed generated packages against it). Its tier rules are in "Generated-output surface" below.

The surfaces share a semver tag but have independent version-bump triggers, documented below.

### Excluded from the v1.0 Go-API compatibility promise

Two packages are **outside** surface 1 for the purpose of the v1.0 promise, and stay changeable at a minor version after the 1.0 tag:

- **`lsp/`** — the language-server implementation and its options. It is consumed through the `yammm-lsp` binary and the VS Code extension, both of which ship in lockstep with the library tag, so its Go API has no independent consumer to stabilize for.
- **`format/`** — the formatter entry points, consumed through the `yammm` CLI and the LSP on the same footing. Both ship in lockstep with the library tag, which is the whole ground for the exclusion: it does not depend on whether some other Go consumer exists.

Both remain covered by the wire and CLI expectations that surround them: a formatter output change is still a behavior change, and an LSP protocol change is still governed by LSP's own versioning. What the exclusion drops is only the Go-symbol compatibility promise. Decided 2026-08-17 during the pre-1.0 exported-surface review, ahead of the v0.12.0 tag.

## Pre-1.0 policy (current)

yammm is currently pre-1.0. Under Go module semver conventions, `0.X.Y` releases are understood to be unstable — backward-incompatible changes are permitted at minor-version bumps — but yammm's own policy is narrower than that. The following rules apply:

### Minor releases (`v0.X.0 → v0.X+1.0`)

- **Additive API changes** — new exported symbols, new option types, new methods on existing types, new struct fields added at the end of a struct (subject to the type's own versioning contract, if any). Consumers written against the prior release continue to compile and run unchanged.
- **Subtractive and breaking API changes** — removal of exported symbols, and breaking changes to an exported symbol's signature, name, or type (e.g. changing a method's return type, renaming an exported function, or collapsing two carrier types into one), provided (a) a grep across the known consumer set returns **either** zero external Go references **or** external references confined to a consumer that pins an older yammm release and whose migration is tracked as a downstream backlog item — in which case the semver pin carries the coordination, so tagging the breaking release cannot break that consumer's build and the migration lands on the consumer's own schedule; (b) the change is explicitly documented in the release notes; and (c) the release-notes entry enumerates every removed, renamed, or signature-changed symbol for downstream auditing.
- **Behavior tightenings** — changes where the only observable difference is that a previously-erroring call becomes a no-op for input that was already semantically equivalent to the stored state, or similar correctness-preserving narrowings (e.g., `Registry.Register` becoming idempotent for exact-`SourceID` + exact-`StructuralHash` re-registration in v0.3.0). Documented in the release notes with the specific contract change.
- **Wire-format additions** — new optional fields added under the `omitempty` + header `features`-signal convention, provided the new field's absence in an older reader does not cause silent data loss. A v0.X reader consuming a v0.X+1-produced document skips the unknown field; a v0.X+1 reader consuming a v0.X-produced document reads missing fields as their zero value.

### Wire-format-incompatible changes

Any wire-format change whose absence in an older reader would cause **silent data loss** is required to:

1. **Increment the header's `version` field** (e.g., `1` → `2`).
2. **Rely on yammm's existing unknown-version-rejection semantics** — older readers encounter the new version and return Error-severity `E_SNAPSHOT_UNSUPPORTED_VERSION` rather than partial-parsing a document they do not fully understand.
3. **Document the bump and the asymmetric-reader semantics** in the release notes: which older versions accept the new file (if any — typically none), which newer versions accept the older file (typically the immediately-prior N versions, losslessly).

The canonical example is v0.3.0's `UnresolvedEdge.Properties` addition: the new wire field cannot be `omitempty`-safe alone because a pre-v0.3.0 reader would silently drop edge properties on cross-batch unresolved edges. The v1 → v2 bump forces pre-v0.3.0 readers to reject cleanly; v0.3.0+ readers accept both v1 and v2 files (v1 files have no Properties to drop, so the read is lossless).

Wire-format version bumps are permitted at minor-version bumps during pre-1.0 (they are the yammm-native signal for "this format has diverged"); they are not deferred to major bumps under pre-1.0.

### Patch releases (`v0.X.Y → v0.X.Y+1`)

- Bug fixes that preserve the public API and wire format.
- Documentation-only changes.
- Internal refactors, test improvements, and dependency updates.
- **Additive API changes** — new exported symbols whose addition leaves every existing signature and documented behavior unchanged; consumers written against the prior release continue to compile and run unchanged. **Amended 2026-08-18:** a new struct field added at the end of an existing struct also qualifies, provided no consumer is licensed to construct the type positionally — the type is documented as constructed by this library and returned to the caller, or the measurement finds no positional composite literal of it in this module or in the known consumer set. A trailing field on such a type cannot break a build. The minor clause's broader form still governs a struct a consumer is expected to build.

Patch releases never introduce breaking changes: no removed or renamed exported symbols, no signature changes, no tightenings of documented behavior, and no wire-format changes. Anything in those categories requires at least a minor release.

## Generated-output surface (`adapter/gogen`)

For an unchanged schema, unchanged `Marshal` options, an unchanged module root, and an unchanged yammm version, generated output is byte-identical (all walks and name assignments are deterministic).

The module root is an input because the embedded source keys and `SerializedEntry` are relative to it. It is the root the caller supplied, the directory of the nearest ancestor holding a `yammm.mod` marker, the synthetic root under `WithSyntheticRoot`, or the entry file's own directory — so committing a marker above a schema changes those keys for an otherwise unchanged generation. A generator that passes the root explicitly sees no change. Across versions, changes to the output classify as:

### Breaking (major post-1.0; pre-1.0 minor under the standard subtractive rules)

- Renaming or removing any emitted identifier derived from an unchanged schema: struct names, field names, named DataType/enum types and their value constants, `EDGE_` struct names, `Graph` fields, or the `SerializedModel` / `SerializedModelEntry` / `SchemaHash` declarations.
- Changing the type-mapping table (e.g. `Integer` → anything other than `int64`), the pointer-optionality rules, the json-tag shape, or the `Where`-block contract of `EDGE_` structs.
- Changing the `SerializedModel` re-load semantics (the documented `LoadString` / `LoadSourcesWithEntry`-with-`"."` recipes) or the meaning of `SchemaHash` (`schema.StructuralHash`).

### Additive / behavioral (minor or patch, release-noted)

- New emitted declarations. **Widened 2026-08-18:** the clause read "in support of new schema features", which did not cover a declaration added for a reason other than a DSL feature — v0.12.3's uniform `SerializedSources` / `SerializedEntry` pair supports no new schema feature and is additive on the same footing. A new declaration renames and removes nothing, so the Breaking tier's first bullet still governs anything that does.
- Identifier derivation for new inputs (e.g. additions to the default initialisms set) — existing identifiers for existing inputs must not change.
- Byte-level changes that rename no identifier and change no semantics (comment text inside the generated file, formatting). Consumers that byte-pin via drift gates will see these and regenerate; the release notes must call them out.

### Explicitly uncommitted

- Doc-comment prose inside generated files.
- Declaration order beyond "deterministic for a given yammm version".

The golden corpus under `adapter/gogen/testdata/` is this contract's executable form: a golden may change only in a release whose notes account for the change under the tiers above.

## Post-1.0 policy (future)

After the `v1.0.0` release, yammm commits to the stricter semver contract that consumers expect from a stable library:

### Major releases (`vN.X.Y → vN+1.0.0`)

- Removes an exported symbol.
- Changes an exported symbol's signature (parameter types, return types, method set).
- Tightens an exported contract in any way that changes observable behavior (errors become silent, nil returns become non-nil, success paths change their side-effect shape).
- Bumps the `.ys` wire format version.
- Introduces a new required field, new required option, or any other change that forces consumers to update call sites.

### Minor releases (`vN.X.Y → vN.X+1.0`)

- New exported symbols (types, functions, methods, constants).
- New options that default to pre-existing behavior when omitted.
- New wire-format fields with `omitempty` semantics that do not trigger silent data loss on older readers.
- Documentation, test, and internal-refactor improvements that preserve the public API surface.

### Patch releases follow pre-1.0 patch-release rules verbatim

## v0.5.0 under this policy

v0.5.0 bundles additive feature work (Go source generation, internal dispatch hardening) with one **breaking contract tightening** (schema-level primary-key enforcement). The Go API symbol surface and the `.ys` wire format are unchanged — code written against `v0.4.x` compiles and runs unchanged — but the **schema-loading contract is tightened**: a schema that loaded cleanly under `v0.4.x` can now be rejected (see the primary-key-enforcement bullet).

- **Additive API surface (`adapter/gogen`)** — a new leaf adapter package exporting `Marshal(s *schema.Schema, opts ...Option) ([]byte, error)`, the `Option` type, and the `WithPackageName` / `WithInitialisms` options. It generates Go source from a schema (one struct per type, named Enum/DataType types, owner-qualified `EDGE_` association structs, a `Graph` aggregate, and an embedded `SerializedModel`) and is schema-in, bytes-out — it imports the Primary API and is never imported back, consistent with the documented adapter-layer discipline. Strictly additive. Justified under the pre-1.0 "additive API changes" rule.
- **Additive CLI surface** — a new `yammm gen --to go <schema.yammm>` command (`cmd/yammm`), sibling to `export`, with `--package`, `--output`, and `--initialisms` flags. The CLI binary is outside the two formally-versioned surfaces (Go API + `.ys` wire format); the addition is backward-compatible (no existing command changes), noted here for completeness.
- **Internal hardening (no API impact)** — the `//exhaustive:enforce` rollout to the seven remaining `schema.ConstraintKind` dispatch switches (so a newly-added kind fails CI rather than reaching a backend un-handled), and the new `internal/ident.ToUpperCamelInitialisms` mechanism that `adapter/gogen` reuses. Both are internal — `internal/*` carries no compatibility guarantee — and change no exported behavior.
- **Breaking schema-loading tightening (primary-key enforcement + extends resolution)** — schema completion now rejects three schema shapes that loaded cleanly under `v0.4.x` via `schema.Load` / `LoadString` / `LoadSources`: (1) every **concrete** (non-abstract, non-part) type must declare or inherit at least one `primary` field, else `E_NO_PRIMARY_KEY`; and (2) an **association** (`-->`) must target a **concrete** type — an abstract target is now rejected with `E_INVALID_ASSOCIATION_TARGET` (a part target already was); and (3) a **concrete** type whose `extends` clause names a **qualified** supertype that does not resolve — an undefined import alias, or a type absent from the imported schema — is now rejected with `E_UNKNOWN_TYPE` when the load supplies a registry (every source-backed load does); previously such a reference was silently deferred, dropping all inheritance from that supertype with no diagnostic (an unqualified unknown supertype already errored). For (1) and (2), a node needs identity to enter a graph or be addressed by an edge, so both checks are hoisted from graph-construction / generation time to load time; (3) brings qualified `extends` resolution in line with the existing unqualified-supertype and relation-target handling. This tightens an exported contract (the schema-loading success path now errors for inputs it previously accepted) — normally **major-requiring**, but permitted in this pre-1.0 minor under the **amended rule (a)**: the affected inputs are `.yammm` schemas, and the only external consumer was pinned to an older release and migrates on its own schedule, so tagging `v0.5.0` cannot break its build. Per conditions (b)/(c), the release notes enumerate the three newly-rejected schema shapes and their diagnostic codes. (Composite primary keys — multiple `primary` fields — are **not** new; they were always supported, and v0.5.0 only corrects documentation that wrongly said "exactly one", which is not a breaking change.)

The `.ys` wire format is unchanged at v0.5.0 (header `version` stays `2`); `adapter/gogen` neither reads nor writes `.ys` (its embedded `SerializedModel` is verbatim `.yammm` source, re-loadable via `schema.LoadString` / `LoadSourcesWithEntry`). The shape of gogen's generated Go output (struct layout, `EDGE_` / `Graph` naming, `SerializedModel` form) is pinned by the package's golden corpus but is **not** yet a formally versioned surface under this policy; if a downstream consumer comes to depend on that shape, a future revision can promote it to a committed surface. The additive surface is documented inline in the v0.5.0 release notes with pointers back to this document's relevant policy sections.

## v0.6.0 under this policy

v0.6.0 closes two gogen feature requests and folds in the test-infrastructure review that followed. The release carries bug fixes and additive API plus one **breaking test-helper surface reduction** — the removal set below is what lifts the release from the patch tier (where this work was first drafted as v0.5.2) to a minor:

- **Bug fix (restores documented behavior) — module-root-relative `SerializedModel` keys.** `adapter/gogen`'s package documentation has always promised module-root-relative embedded keys and a re-load that "needs no filesystem"; the implementation relativized against the entry schema's directory and silently fell back to cwd-relative disk reads when the load's module root differed (registry-style layouts: `schema.Load` + `WithModuleRoot(repoRoot)`). Keys now derive from the load's recorded module root (`Schema.ModuleRoot()`), so they match the import statements inside the sources and the embedded model re-loads hermetically from any working directory. `Marshal`'s round-trip self-check now runs with `WithSourcesOnly`, so a key regression fails generation loudly instead of being rescued by on-disk files. Generated bytes change only for module-root ≠ entry-dir loads (the shapes that were previously self-contradictory) plus one added comment line in the multi-source re-load instructions; the pre-existing golden corpus is otherwise byte-identical.
- **Bug fix — in-memory source keys resolve textually.** `LoadSources` / `LoadSourcesWithEntry` pre-registration resolved each joined key path against the filesystem (symlinks included) whenever it happened to exist on disk, while import lookup never did — so a root-relative key reachable through a symlinked directory registered under a different `SourceID` than the one import resolution computed. Under `WithSourcesOnly` that mismatch failed the load (and therefore `gogen.Marshal`'s round-trip self-check) for schemas that load fine from disk, dependent on the process working directory's contents. Root-relative keys now derive textually from the canonical module root on every path — pre-registration, entry selection, import lookup, and the sandboxed disk reads — making in-memory resolution independent of disk state. Absolute keys (the LSP overlay shape) still canonicalize like entry paths so they land in the same path regime as the module root.
- **Bug fix — cross-Load registry cache hits now carry their sources.** A shared-`WithRegistry` load whose import short-circuited to a registry-cached schema produced a `Schema` whose `Sources()` lacked the cached import's content — breaking closure-content consumers (gogen's embedded model; cross-import diagnostics rendering). The cache-hit path now copies the cached schema's transitive closure content into the new load's source registry. The copy memoizes per load — a diamond-shaped import graph is walked per schema, not per import path — and a copy that collides with different pre-registered bytes under the same `SourceID` surfaces as `E_INTERNAL` instead of silently leaving `Sources()` divergent from the compiled import.
- **Bug fix (restores documented behavior) — float exponents without a sign.** The lexer's exponent fragment required an explicit sign, rejecting the signless form the published numeric-literal grammar documents — the grammar's own example `2.5e10` failed to load with `E_SYNTAX`. The sign is now optional, so previously-rejected spec-conformant schemas load; signed forms are unchanged.
- **Diagnostics — malformed numeric literals are named at the literal.** A numeric literal running straight into identifier characters (`0x10`, `42abc`, a broken exponent) now lexes as one malformed token, and the load reports `malformed numeric literal "0x10": numeric literals are decimal (hexadecimal and suffixed forms are not supported)` spanning the literal itself — previously the error was a `mismatched input` pointing at whatever happened to follow. The code stays `E_SYNTAX`; no new diagnostic codes. One pathological acceptance change rides along, enumerated for completeness: the word operator `in` written flush against a preceding number (`1in [1, 2]`) previously token-split and parsed; it is now a malformed literal and requires whitespace, like every other operand boundary already did in practice.
- **Breaking — `snapshot/snapshottest` surface reduction.** The package's exported surface was rebuilt around structural round-trip assertions. Removed: `BuildTestSnapshot`, `Record`, `CompareSnapshots`, `ReadGolden`, `UpdateGolden`, `State`, `ExpectDirState`, `ExpectMetadataPreserved`. Signature change: `AssertDeterministic` drops its unused `*schema.Schema` parameter. Replacements: `DiffSnapshots` (go-cmp structural comparison — recursive over composition trees, provenance-presence-aware, exact for same-typed numerics) supersedes `CompareSnapshots`; `BuildSnapshot` supersedes the `BuildTestSnapshot`/`Record` pair for pre-validated instances; golden read/write/update moved to internal test support. Justified under the amended pre-1.0 rule (a): the only external consumer was pinned to an older release and migrates on its own schedule. Per conditions (b)/(c), this enumeration is the removed-symbol audit record.
- **Breaking — `schema.WithSourceRegistry` unexported.** The load option's parameter type lives in `internal/source`, which external consumers cannot import or name — the only argument expressible outside the module was an untyped nil — so the symbol was public in name only. It is now unexported. Its sole consumer, the in-module LSP analyzer, instead copies the loaded schema's source closure from the public `Schema.Sources()` accessor after the load. Rule (a) is satisfied trivially: no meaningful external reference was ever constructible. Enumerated here per conditions (b)/(c).
- **Breaking — `schema.Builder` name validation.** `Build()` now rejects (`E_INVALID_NAME`) declared names that do not match the DSL's own name productions: type and datatype names must match `UC_WORD` (`[A-Z][A-Za-z0-9_]*`), property names `LC_WORD` (`[a-z][A-Za-z0-9_]*`), and relation names either form (`[A-Za-z][A-Za-z0-9_]*`). Previously the Builder checked names only for emptiness — its own `validateInput` documentation already promised rejection of "empty/invalid identifiers" — so it admitted schemas the DSL cannot express (e.g. `AddType("Foo-Bar")`), which could not round-trip to `.yammm`, mangled through gogen identifier generation, and surfaced only as label collisions at neo4j export. Schema names and invariant names map to quoted strings in the DSL and stay free-form; import aliases were already validated during completion (`E_INVALID_ALIAS`). A correctness consequence: `adapter/neo4j.SanitizeIdentifier` is the identity function on every production-conformant name, so two distinct type names from either schema front door can no longer collide after sanitization — `DetectLabelCollisions` is retained as defense-in-depth. This tightens an exported contract — permitted in this pre-1.0 minor under the amended rule (a): the only external consumer was pinned to an older release and migrates on its own schedule. The affected front door is the programmatic `Builder`; `.yammm` source loading via `Load` is unchanged. Per conditions (b)/(c), the newly-rejected input classes are the three production mismatches enumerated here.
- **Additive API surface (`schema`)** — `Schema.ModuleRoot()` (the canonicalized module root the load resolved module-style imports against; `""` when none was in play) and the `WithSourcesOnly()` load option (import resolution restricted to pre-registered in-memory sources; a miss is `E_IMPORT_RESOLVE`, never a filesystem read).
- **Additive API surface (`diag`)** — `Result.HasCode(code Code) bool`, the code-presence predicate alongside the existing severity predicates.
- **Additive API surface (`instance/instancetest`)** — a new test-support package exporting the `VI` instance builder (`VI(typeName string, opts ...VIOption) *instance.ValidInstance`) and its options (`TypeID`, `PK`, `Props`, `Edges`, `Composed`, `Provenance`), the shared constructor for pre-validated instances across the graph, snapshot, and adapter test suites.
- **Additive API surface (`snapshot/snapshottest`)** — `BuildSnapshot` and `DiffSnapshots`; see the breaking bullet for what they replace.
- **Additive API surface (`lsp`)** — `Config.DebounceDelay time.Duration`, the delay between a document change and the analysis it triggers (zero or negative means the 150ms default). Promotes a workspace-internal test-only setter into real configuration; existing `Config` literals compile and behave unchanged.
- **Additive CLI surface** — `yammm gen --module-root <dir>` resolves module-style imports against a root other than the schema's own directory; without it, registry-layout schemas could not be generated by the CLI at all. CLI diagnostics across all schema-loading subcommands now relativize locations against the loaded schema's module root (canonical, symlink-resolved), so rendered paths stay root-relative regardless of symlinks in the invocation path. `yammm-lsp` gains a `--debounce-delay <duration>` flag exposing the new `lsp.Config.DebounceDelay` (0 keeps the 150ms default).
- **Surface promotion** — generated Go output is now the third formally versioned surface (Scope item 3 + the "Generated-output surface" tier rules above). A documentation/policy commitment; precedent for landing a policy edit alongside a release is v0.5.1's amendment of the patch rule itself.

The `.ys` wire format is unchanged at v0.6.0 (header `version` stays `2`).

## v0.7.0 under this policy

v0.7.0 bundles the diagnostic-completeness rework (behavioral — one load pass reports every independent error exactly once) with one **breaking schema-loading tightening** (unknown property datatypes). The Go API symbol surface gains three additive `diag` symbols; the `.ys` wire format is unchanged.

- **Behavioral — diagnostic completeness.** Schema loading no longer fail-fasts at the first import-declaration error, the first failed import, or the first failing completion phase. On inputs that already failed, strictly more — and more truthful — diagnostics are reported, under the same codes and the same all-or-nothing contract (any error ⇒ nil `*Schema`). The coordinated changes, enumerated:
  - *Import continuation* — every unresolvable or failed import is reported at its own declaration; semantic analysis then proceeds with the failed aliases deferred, so the schema's own diagnostics surface in the same pass.
  - *Structural-rejection continuation* — `LoadString` and `WithDisallowImports` loads still reject import declarations categorically (single `E_IMPORT_NOT_ALLOWED`, never probed), but the rejection no longer suppresses the source's other findings.
  - *Failure memoization* — within one load, a schema that fails to compile is compiled once; each importer still reports its own `E_UPSTREAM_FAIL` at its own declaration (previously a diamond over a broken import would have re-collected the broken schema's diagnostics per importer once continuation landed).
  - *Per-schema error attribution* — a load shared across nested schemas judges each schema by the errors it contributed, so a clean import loaded after a broken sibling compiles and registers instead of drawing a false `E_UPSTREAM_FAIL`.
  - *Keep-first alias binding* — an import alias binds once; a later declaration of a bound alias is reported once (`E_DUPLICATE_IMPORT`, by completion) and stays inert: not loaded, not resolved, not wired. This also fixes a latent mis-wire where the kept import could silently resolve against the last declaration's schema.
  - *Validation ownership* — declaration-level import validation lives in completion (shared by parse and Builder front doors; its alias-collision check now also covers local datatype names — newly rejecting one previously-clean Builder input, carved out in the strictness note below), resolution-level validation in the resolvers; no check is live in two layers, so continuation cannot double-report. The duplicate-resolved-`SourceID` check now visits declarations in source order, deterministically blaming the later declaration (previously map-iteration-dependent).
  - *Cascade suppression* — references through a failed **or completion-rejected** import alias (`extends`, relation targets, property datatypes, primary-key types) defer silently to the root-cause diagnostic; a declared-but-rejected `primary` draws `E_INVALID_PRIMARY_KEY_TYPE` **once at the declaring type** (not re-reported at every inheriting subtype, and never an additional `E_NO_PRIMARY_KEY`); invariant validation skips types with unresolved supertype chains.
  - *Completion gates removed* — all completion phases collect-and-continue; only inheritance-cycle detection keeps a hard gate (linearization requires cycle-free input). Duplicate type/datatype declarations are now all reported (keep-first), not just the first.
  - *Truncation surfacing* — `diag.Collector` counts every issue it *sees* (not only those stored under the limit), so `HasErrors`/`OK`/`ErrorCount`/`SeverityCounts` stay truthful when collection is truncated and the all-or-nothing gate cannot be fooled by a dropped error; the CLI appends a dropped-issues note in text mode and emits the truncation wire fields (`limit`/`limitReached`/`droppedCount`) in JSON mode — now including a truncated result with no rendered errors, previously silent; the LSP logs truncation server-side.

  Two `Builder`-front-door exceptions aside, no input that loaded cleanly under `v0.6.0` is rejected by this stream, and no input that failed under `v0.6.0` loads — verified by strictness controls in the test suite. **Exception 1 (a breaking tightening):** a `schema.Builder` import whose alias equals a *local datatype* name now fails with `E_IMPORT_ALIAS_COLLISION` (the completer's collision check previously consulted only the type index, and the loader's datatype-aware check never ran for `Builder` schemas; the `Load*` front door already rejected this shape at `v0.6.0`, so only the programmatic `Builder` API tightens) — justified under the same **amended rule (a)** as the unknown-property-datatype entry below (the only external consumer was pinned to an older release). **Exception 2 (a loosening):** a registry-less `Builder` (no `WithRegistry`) whose primary key is typed by a qualified datatype (`id other.IdType primary`) previously failed load with a mis-attributed `E_INVALID_PRIMARY_KEY_TYPE`; it now defers that reference to link time and loads clean, consistent with how a registry-less `Builder` already defers a qualified `extends`, relation target, and non-primary property datatype (pinned by `TestBuild_NoRegistryQualifiedPrimaryKey_DefersAtLinkTime`) — a permissive behavioral change (a previously-rejected shape now accepted) needing no special justification. Both exceptions are `Builder`-API-only and production-unreachable (the `Load*` front door always supplies a registry, so only the programmatic `Builder` reaches these cases); schema-author-facing `.yammm` input is unaffected by either. Otherwise the stream is justified under the pre-1.0 "behavior tightenings" rule (more complete reporting on already-failing inputs); minor tier, never a patch.
- **Additive API surface (`diag`)** — `Collector.ErrorCount() int`, the Fatal+Error count alongside the existing predicates (enables before/after comparison when one collector is shared across nested operations); `Result.TruncationNote() string`, the canonical one-line dropped-issues summary ("" when the limit was not reached) so text-rendering consumers share one wording; and `IsImportDeclarationCode(code string) bool`, which classifies a rendered diagnostic-code string as an import-*declaration* diagnostic (rejected / duplicate / colliding / invalid alias) versus an import-*resolution* one, co-located with the code definitions so the LSP markdown surface's Hint-downgrade list cannot drift from the codes (a `CategoryImport` partition-guard test pins every import code to exactly one family).
- **Breaking — unknown property datatype tightening.** Property datatype references that loaded silently under `v0.6.0` are now rejected at load with `E_UNKNOWN_TYPE`: (1) an **undeclared local name** (`a Mystery` with no `type Mystery = …`); (2) a **qualified reference whose import resolves but lacks the datatype** (`a other.NoSuchType`) — including a property typed by an imported *type* rather than a datatype, which the DSL grammar does not back (a property's type must be a built-in or a datatype alias; type references belong in relations); and (3) a **qualified reference whose qualifier names no declared import** (`a nope.SomeType`). Previously all three loaded cleanly and the failure surfaced per-value at instance-validation time ("unresolved alias constraint") — or never, for an optional property absent from the data. References through a declared-but-failed import remain silent (the import failure is the root cause), and Builder/deferred completion flows without a registry or resolution map keep their deferred posture. One attribution correction rides along: an unknown-named `primary` property previously failed load with a mis-attributed `E_INVALID_PRIMARY_KEY_TYPE` ("Alias cannot be used as a primary key"); it now fails with the root-cause `E_UNKNOWN_TYPE` — no input flips between accept and reject, only the code changes. This is the same class as v0.5.0's loading tightenings — normally major-requiring, permitted in this pre-1.0 minor under the **amended rule (a)**: the only external consumer was pinned to an older release and migrates on its own schedule. Per conditions (b)/(c), this enumeration is the newly-rejected-shapes audit record.

The `.ys` wire format is unchanged at v0.7.0 (header `version` stays `2`).

## v0.9.0 under this policy

v0.9.0 carries two independent streams. The headline is **schema annotations**: a validated `@name` / `@@name` decorator mechanism on the DSL, whose first consumers are Neo4j index DDL and a write-once node-write shape. The second closes the two instance-layer edge-validation root causes surfaced by the jschema contract-alignment suite — schema completion never resolved datatype-alias constraints on association edge properties, and the instance layer re-resolved relations' declaring-schema-relative target names against the entry schema.

Minor-tier. The annotation stream is additive across the DSL, the Go API, and the CLI, with behavior changes on existing surfaces (two CLI commands, the Neo4j node-write shape for annotated types, and — confined to failing loads — the `E_PROPERTY_CONFLICT` reporting shape); the edge-validation stream carries a breaking schema-loading tightening, a data-validation tightening, and two additive API symbols.

### Schema annotations

- **Additive DSL surface — annotations.** A property may carry trailing `@name` / `@name(args)` decorators, and a type body may carry `@@name(args)` members (optionally doc-commented). The blessed v1 set is `@index` (single-property range index), `@@index(p1, p2, …)` (composite, order significant), `@vector(cosine|euclidean)`, and `@writeOnce`; the set is curated in the core, with no external registration API. Annotations are validated at load after inheritance linearization, and inherited through it — a subtype's set is the **union across its direct supertypes' own resolved views**, so a marker like `@writeOnce` cannot be dropped by `extends` order, and a type's deliberate shadowing binds its own subtypes rather than being undone by a grandparent's copy. Never declaring an annotation and deliberately dropping one are distinguished: when one supertype carries an annotation that another dropped, the two disagree and the load reports `E_INVALID_ANNOTATION` rather than silently picking a side; re-declaring the property on the subtype, with or without the annotation, settles it. **Purely grammar-additive:** `@` previously lexed as a token that appeared in no rule, so every annotation-bearing schema was a syntax error. No previously-valid schema parses differently or changes meaning. See [SPEC.md](SPEC.md#annotations) for the full surface and its diagnostics.
- **Additive API surface (`schema`) — the annotation model.** `Annotation` (`Name`, `Args`, `Documentation`, `Span`); `AnnotationArg` (`Text`, `Kind`, `Span`); `AnnotationArgKind` with `ArgUnvalidated` / `ArgPropertyRef` / `ArgKeyword`; `AnnotationPlacement` with `PlacementProperty` / `PlacementType`; `AnnotationSpec` (`Name`, `Placement`, `Documentation`, `ArgHint`) with `AnnotationSpecs()` — a read-only view of the built-in registry for editor tooling, not a registration API — and `VectorSimilarityFunctions()`, so tooling cannot offer a keyword the loader rejects. Accessors: `Property.Annotations()` / `AnnotationsSlice()` / `Annotation(name)`, and `Type.Annotations()` / `AnnotationsSlice()` / `AllAnnotations()` / `AllAnnotationsSlice()` (own, and own-plus-inherited). Builder entry points: `TypeBuilder.WithTypeAnnotation(name, args...)` and `TypeBuilder.WithPropertyAnnotation(propertyName, name, args...)`, both routed through the same completion-phase validation as the parse front door. Justified under the pre-1.0 "additive API changes" rule.
- **Additive API surface (`schema`) — merged-view property identity.** `Property.Origin() *Property` returns the property **as declared** — itself when nothing was merged. It exists because annotation union can make an entry in `Type.AllProperties()` / `AllPropertiesSlice()` a *synthesized copy* rather than the `*Property` its declaring type holds in `PropertiesSlice()`, which silently broke the pointer-keyed lookups three generator adapters relied on. Any map built from declared properties and read back over a merged view must key through `Origin()`; everything it discards is annotation state (name, constraint, datatype reference, optionality, primary-key status, span, and declaring scope are all preserved on the copy). Additive symbol, but a **contract that identity-keyed consumers must adopt** — documented in [API.md](API.md#annotations).
- **Additive diagnostic codes (`diag`)** — `E_UNKNOWN_ANNOTATION`, `E_UNKNOWN_ANNOTATION_TARGET`, `E_INVALID_ANNOTATION`, `E_INVALID_ANNOTATION_TARGET`, and the Warning-severity `W_ANNOTATION_SHADOWED` (a type's own re-declaration shadows an inherited annotated property without re-stating the annotations, silently dropping them). `adapter/neo4j` adds `E_NEO4J_UNKNOWN_PROPERTY` (an index annotation naming a property the type does not have) and `E_NEO4J_INVALID_INDEX_TARGET` (one naming a property whose type cannot carry it — `@index` on a non-scalar, `@vector` on a non-Vector or on a non-positive dimension). Both are reachable only where load-time validation had to defer, on a type whose supertype never resolved and on every qualified reference in a registry-less `schema.Builder` schema. No existing code changes meaning; no schema that loaded clean at v0.8.0 gains a diagnostic, since annotations could not parse.
- **Additive API surface (`adapter/neo4j`) — index emission and diffing.** `IndexKind` (`IndexRange`, `IndexVector`) and `Index` (name, kind, label, properties, vector dimension/similarity, complete `CREATE … IF NOT EXISTS` statement); `Adapter.IndexesForSchema` (statements) and `Adapter.IndexesStructured` (values); `Adapter.DiffIndexes` with `IndexDiffResult` (`Match` / `Drift` / `Create` / `Drop` / `Unverified`), `IndexMatch`, `IndexDrift`, and `IndexUnverified`; `IndexKind.String()` so an `Index` renders as `RANGE`/`VECTOR` rather than a bare ordinal. `RemoteIndex` gains `Options map[string]any`, `State`, and `OwningConstraint` fields **at the end of the struct**, plus `VectorDimensions()`, `VectorSimilarity()`, and `IsOnline()` accessors. `ConstraintDiffResult` gains an end-of-struct `Unverified []ConstraintUnverified` field with the `ConstraintUnverified` type. `NodeShape` gains an end-of-struct `ImmutableKeys []string`. `ImmutableKeysFor(t *schema.Type) []string` exposes a type's derived `@writeOnce` keys. Justified under the pre-1.0 "additive API changes" rule (the `RemoteIndex` field under its end-of-struct clause).
- **Behavior change — `IntrospectIndexesQuery()` returns a widened query over a wider row set.** Two changes, and a direct caller of the returned string is exposed to both. The projection now also yields `options` (vector-index configuration) and `state` (so an index that exists but serves no queries is distinguishable from a healthy one); executing it against a server that does not support those columns fails where it previously succeeded, so the widening is effectively a server-version requirement. Separately, the `WHERE owningConstraint IS NULL` clause is **gone**: the query now returns constraint-backing indexes alongside standalone ones, filtering only `LOOKUP`. Those rows are what let the diff see that a backing index holds its constraint's name against every `CREATE INDEX` and already serves the definition it covers — both conditions under which the server silently no-ops a declared index. A consumer that filtered on the query's behalf must now test `RemoteIndex.OwningConstraint` itself rather than assume the rows were excluded. `yammm neo4j diff` handles an unsupported server by degrading (see below); a direct caller does not.
- **Behavior change — `@writeOnce` changes the emitted Neo4j node-write shape.** The effective immutable-key set for a written type is now `WithImmutableKeys` ∪ the type's derived `@writeOnce` keys. A node whose effective set is non-empty is written with the split `ON CREATE SET` / `ON MATCH SET` shape, and `$update_props` excludes every member of that set; `BatchNodeQueries` selects the shape **per type**, so an annotated type gets the split shape while an unannotated type in the same snapshot stays mutable. A non-empty explicit list still produces the split shape for every written type, preserving the prior contract, and only the explicitly-passed keys are validated against the schema (the derived ones come from validated annotations by construction). A schema with no `@writeOnce` emits byte-identical single-node Cypher to v0.8.0. The guarantee does not depend on the caller holding a `*schema.Type`: the derived keys travel on `NodeShape.ImmutableKeys`, so `NodeQueryFor` honors `@writeOnce` even in the documented streaming call shape that passes a nil schema type — which previously got the mutable shape and silently overwrote every `@writeOnce` property on each re-ingestion MERGE.
- **Breaking change — `BuildBatchNodeMergeQuery` reads merge keys from a `key_`-prefixed row entry.** The emitted template now matches on `row.key_<name>` rather than `row.<name>`, and `Adapter.BatchNodeQueries` builds its rows to match, so the pair stays consistent and callers using the adapter entry point are unaffected. A caller using the exported builder **and** assembling its own rows must add the prefix. The prefix is what the single-node builder has always used for its parameters (`$key_<name>`); the batch row lacked it, so merge keys shared one namespace with `props` and `update_props` and a type whose primary key was itself named `props` or `update_props` — both legal DSL property names — had its key value overwritten by the property map, making every MERGE in the batch match on a map. That path became reachable without any caller opt-in once `@writeOnce` began selecting the split shape on its own.
- **Breaking API change — `DiffConstraints` and `DiffIndexes` take an `*OwnedLabels`, not a schema name.** `Adapter.OwnedLabels(ctx, s)` returns the exact set of labels the adapter emits for a schema — the same walk the emitters use — and both diff entry points scope themselves to it. Ownership is set membership rather than a rule applied to each remote object's label. This is breaking for `DiffConstraints` (`DiffIndexes` is new at v0.9.0 and unreleased); the CLI computes the set once and passes it to both halves.

  The change is not a refinement of the previous prefix test but a replacement for it, because no such test can be correct. `Adapter.Label` composes a label from a caller-configurable prefix and separator around two sanitized free-form names and is not invertible: a prefix test claimed a sibling schema's objects (`app` claiming everything under `app__legacy` and `app__Core`), anchoring the segment after the prefix still claimed any sibling whose next segment started uppercase, and any anchoring at all was defeated by `WithLabelSeparator("")`. Under set membership none of those inputs matter, and an empty schema name — where `Label` emits bare, unnamespaced labels — owns exactly the schema's own labels rather than either nothing or the entire database.

- **Behavior change — a remote constraint the schema could not have declared is ignored.** `DiffConstraints` now applies the declarability filter its index counterpart already had: relationship constraints (for which `LabelsOrTypes` holds a relationship type, not a label) and node constraint kinds the DSL cannot express are no longer reported as schema-owned orphans to drop, which was drift no schema edit could resolve.

- **Behavior change — desired objects pair with remote ones in three phases.** Both diffs match on name-and-identity together, then on identity alone, then on name alone. Previously, two remote objects sharing one identity (the schema's own plus an operator's ad-hoc definition) were paired positionally, so the classification depended on the order `SHOW INDEXES` / `SHOW CONSTRAINTS` returned rows in — and because those order by name, the diff routinely named the schema's **own** object as the one to drop. A name match whose definitions disagree is reported as drift rather than create-plus-drop: emitted statements carry `IF NOT EXISTS`, so re-creating under a name the database already holds silently does nothing and the plan never converges. Identity outranks name so that a remote object which exactly realises a declaration is not displaced by one that merely holds its name — otherwise the index actually serving the queries is the one the plan drops. A desired index whose name is held by a kind the DSL cannot express (FULLTEXT, TEXT, POINT) is likewise reported as drift naming the holder, since a CREATE under that name would be a permanent no-op.
- **Behavior change — a constraint the server will not fully describe is `Unverified`, not matched.** A TYPE constraint whose enforced type the database does not report (Neo4j < 5.9, or any driver path omitting the column) previously folded into `Match`, so `yammm neo4j diff` exited 0 on a genuinely drifted database. It now lands in the new `Unverified` bucket and exits **3** (`ExitRuntime`), matching how the index half already treated an unreadable vector configuration. Constraint or index drift still outranks it, exiting 1.
- **Behavior change — an index in a non-serving state is reported.** `SHOW INDEXES` lists a `FAILED` index with every column matching its declaration while it serves nothing, so a definition-only comparison called it in sync. A `FAILED` index is now **drift** (drop and recreate); a `POPULATING` one is **unverified** (transient). An unreported state is still treated as online, so older servers and hand-built records are unaffected.
- **Behavior change — colliding index names are disambiguated, not rejected.** The readable index name joins label and property names with underscores, and property names may themselves contain underscores, so `@@index(a, b_c)` and `@@index(a_b, c)` render identically — as do an `a_b` property on type `Item` and a `b` property on type `Item_a`. This was reported as an error; because index emission is all-or-nothing, one such pair suppressed **every** index in the schema and left the user renaming a domain property to get any DDL at all. Colliding names now receive a short deterministic digest suffix. Only names that would actually clash are suffixed, so every other index keeps its readable name, and pairing falls back to semantic identity when a name does not match, so an existing remote index is still recognised after a name changes.
- **Behavior change — `IndexesForSchema` returns nil for a schema with no index annotations.** It previously returned a non-nil, zero-length slice while `IndexesStructured` returned nil, so a caller distinguishing nil from empty got opposite answers from two entry points documented as differing only in shape.
- **Behavior change — MERGE keys are coerced like properties.** Every write entry point (`NodeQueryFor`, `BatchNodeQueries`, `EdgeQueryFor`, `EdgeQueriesFor`, `BatchEdgeQueries`) now binds its merge keys and relationship endpoint keys as the driver-native types the corresponding properties are stored as, using the constraint `ShapeForSchema` records for each primary key. `$props` was always coerced and the keys were not, so for a transforming kind — `Date`, `Timestamp`, `Float` — the MERGE matched on one representation while the SET wrote another: a `Date` primary key matched no stored node, and **every re-ingestion inserted a duplicate**; an association to such a type matched nothing and the edge was silently absent, with `matched_rows` returning a legitimate-looking 0. Affects only schemas with a non-`String`/`Integer`/`UUID` primary key. A hand-built `NodeShape` carries no key constraints and passes values through unchanged, as before. New failure mode: an uncoercible key value is now an error from the query builder rather than a silent mismatch at the server.
- **Breaking API change — `ParamTypesForType` no longer emits merge-key entries; `ParamTypesForMergeKeys` does.** One `ParamTypes` cannot describe both shapes: in a flat row `key_id` is a property so named, while in `BuildBatchNodeMergeQuery`'s row shape the same spelling is the merge key for `id` and the properties live nested under `row.props`. Emitting both meant a declared property named `key_<pk>` silently took the merge key's constraint, or the reverse. `ParamTypesForType(t, prefix)` is now what it was at v0.8.0 — one entry per property — except that it walks the **merged** property set, so an inherited property is covered. `ParamTypesForMergeKeys(t, prefix)` covers the primary keys under the `key_` namespace: prefix `""` for `BuildNodeMergeQuery`'s `$key_<pk>`, `"rows"` for `BuildBatchNodeMergeQuery`'s `row.key_<pk>`. Merge them with `maps.Copy` when the caller's own map carries both. Breaking only against this branch's unreleased shape; v0.8.0's `ParamTypesForType` emitted no merge-key entries either. Callers going through the adapter's write path need none of it — those coerce their own keys.
- **Behavior change — `DiffConstraints` declarability is edition-aware.** Under `WithEdition(Community)` the emitter produces UNIQUE alone, so the diff now also treats a remote NOT NULL or TYPE constraint as a kind this configuration cannot declare. Both sides of the comparison are filtered by one list. Previously the desired side was filtered and the actual side was not, so running `yammm neo4j diff --edition community` against an Enterprise-provisioned database made **every** NOT NULL and TYPE constraint an unmatched orphan and printed it as a drop — a plan whose application removes every required-property and property-type guarantee in the database.
- **Bug fix — the uniqueness constraint type is recognised on every supported server generation.** Neo4j renamed the node uniqueness constraint type that `SHOW CONSTRAINTS` reports: 5.x yields `UNIQUENESS`, 2026.x yields `NODE_PROPERTY_UNIQUENESS`, aligning it with the `NODE_PROPERTY_EXISTENCE` and `NODE_PROPERTY_TYPE` spellings the server has always used. The adapter compared the reported string against its own `UNIQUENESS` spelling, so against a 2026.x server **every UNIQUE constraint yammm emits misreported**, in two places. `DiffConstraints` found the remote constraint undeclarable and excluded it, then found the desired constraint's name taken and reported the schema's **own, correct** constraint as drift with "drop it before this constraint can be created" — under `--edition community`, where UNIQUE is the only kind emitted, that was the entire plan. `InferSchema` marked no primary key from such a constraint, so `yammm neo4j introspect` scaffolded a schema that fails to load on `E_NO_PRIMARY_KEY`. Both spellings are now folded to one before any comparison; `RemoteConstraint.Type` still carries exactly what the server reported, because drift messages echo it. This is a fix to behavior shipped in v0.8.0 and earlier, not to anything new at v0.9.0. The integration suite runs against `neo4j:2026.05.0` and is green on both editions.
- **Additive API surface (`adapter/neo4j`) — comparison scope and constraint-name blocking.** `ConstraintDiffResult` and `IndexDiffResult` each gain an end-of-struct `Excluded int`, counting the remote objects that entered **no** bucket because the comparison had nothing to say about them: the schema owns no label they carry, or they are of a kind it cannot declare. It exists so "0 to drop" cannot be read as "the database is accounted for" — objects left behind by a type deleted or renamed since the last apply sit on a label no current type declares, and ownership derived from the schema cannot name them. `Adapter.DiffIndexes` gains a variadic `alsoBlocking ...RemoteConstraint` (mirroring `DiffConstraints`), because a NOT NULL or TYPE constraint has no backing index and so appears in no `SHOW INDEXES` row, while its name still occupies the namespace indexes and constraints share. `ConstraintKind` gains `String()`, matching `IndexKind`. Existing calls compile unchanged.
- **Additive CLI surface** — a new `yammm neo4j indexes <schema.yammm>` command emitting index DDL from a schema's annotations, and a `--indexes` flag on `yammm neo4j diff`. The three `neo4j` subcommands now share one flag definition, because `diff` computes its desired side exactly as `constraints` and `indexes` emit it and a flag one command has and another lacks is a plan reporting drift the operator never introduced: `--separator` and `--prefix` on all three, and `--named`, `--edition`, `--node-keys`, `--scalar-types`, `--required-only-types` on `constraints` and `diff`. `indexes` takes neither the edition nor the constraint-shape flags — range and vector indexes are core query features on both editions, so there is nothing to gate. Outside the formally-versioned surfaces; noted for completeness.
- **Breaking CLI-behavior change — `yammm neo4j diff` now diffs indexes by default.** Schema annotations give the schema a vocabulary for indexes (`@index`, `@@index`, `@vector`), and `neo4j diff` compares them the way it has always compared constraints: an index in the database that the schema does not declare is reported as a **drop**, and drift, creates, and drops all fold into exit code 1. An invocation that previously exited 0 against a database carrying an operator- or pipeline-created index on a schema-owned label now exits 1. This is drift by the feature's definition — the remedy is to declare the index, and drops are reported, never applied — but it changes an existing command's exit code, so it is enumerated here.
  - `--indexes=false` restores exact constraints-only behavior, exit code included. Indexes are still **fetched** under it, because index and constraint names share one Neo4j namespace and the constraint half needs the index names to know whether a `CREATE CONSTRAINT` would silently no-op; the flag opts out of comparing indexes, not out of classifying constraints accurately. A server that cannot report indexes prints a warning and the constraint half degrades, but the flag never changes a constraint's classification by itself.
  - Only index kinds the DSL can express participate. `SHOW INDEXES` also reports FULLTEXT, TEXT, POINT, 4.x BTREE, and relationship indexes; those are ignored rather than reported as drops, since no schema edit could resolve them.
  - Two new non-zero outcomes, both meaning "the index half could not be completed", both exiting **3** (`ExitRuntime`) rather than reporting success for a comparison that never ran: an index whose vector configuration the server does not report is listed as **unverified** (never folded into the matched count), and a failed index introspection prints a warning and degrades to constraints-only. Constraint or index drift still outranks either, exiting 1.
  - A third exit-**3** outcome guards a failure that would otherwise be silent: an introspected constraint or index that parsed a **name but no type**. The parsers accept records from any source and return zero values for a field they cannot read, so a `type` column that stopped arriving — a rename, or a projection narrowed by a caller — would empty that field on every record, make every object undeclarable, and leave the command printing a confident plan built from a partial reading. Because the command knows which projection it issued, it treats a named-but-untyped record as a broken read: it names the count and the query on stderr and reports no comparison at all. A record whose type is present but *unrecognised* is a different case and is unaffected — that is an undeclarable kind, which the diff already accounts for.
- **Behavior change — CLI commands now print warnings, from every phase.** `cli.RenderResult` previously rendered only when a result carried an error, so a warnings-only result printed nothing in any command, `yammm validate` included; nine of the ten schema-loading commands additionally reached the renderer only on failure. Both are fixed: every command renders whatever it produced, at any severity, to **stderr**. Exit codes are unchanged (a warning is not a failure) and no command's stdout contract is affected. This is what makes `W_ANNOTATION_SHADOWED` — the only signal that a subtype re-declaration dropped an inherited `@writeOnce` — reachable. **It also surfaces warnings that already existed but no command printed**, so an unchanged, still-passing input may emit new stderr output at v0.9.0. The full set:
  - A schema using `-_` in a constraint bound has always drawn a Warning-severity `E_INVALID_CONSTRAINT` ("minus sign before `_` (unbounded) has no effect").
  - `yammm snapshot verify` now prints the decoder's Warning-severity `E_SNAPSHOT_PATH_FALLBACK` (a provenance path that fails `path.Parse`) and `E_SNAPSHOT_UNSUPPORTED_HASH_ALGORITHM`, on an otherwise unchanged `.ys` file. With `--format json` it prints a wire object where it previously printed nothing.
  - `yammm export` from a `.ys` snapshot, and `yammm snapshot save --into`, print the same snapshot-decoder warnings. Both previously gated on error severity, so an operator could ship an export believing integrity had been verified when it had not.

  Library callers are unaffected throughout — the `Result` always carried these.
- **Behavior change — one diagnostic document per invocation.** A command now renders **exactly one** `diag.Result`: a phase whose diagnostics do not end the run folds them into the result the command reports last. This is a wire-contract fix for `--format json`, where every render writes one complete JSON document and two concatenated on stderr are not parseable — reachable as soon as load warnings became renderable, in any command that loads a schema and then does something else (`check`, `load`, `export`, `snapshot save`, `snapshot verify`, `neo4j diff`, `neo4j constraints`, `neo4j indexes`, `gen`). Text output is unaffected apart from ordering: previously-separate diagnostic blocks now render as one sorted block.
- **Behavior change — the issue limit retains the most severe issues.** `diag.Collector` dropped whatever arrived after its cap, regardless of severity. It now retains the `limit` most severe issues seen, ties broken by arrival order: at the cap, an incoming issue more severe than the least severe stored one takes its slot. `Result.DroppedCount` still reports seen-minus-retained and the severity gates were always seen-based, so `OK`/`HasErrors`/`SeverityCounts` are unchanged; what changes is **which** issues a truncated `Result` can enumerate. This closes a starvation path the annotation stream opened — `W_ANNOTATION_SHADOWED` is collected during inheritance linearization, ahead of every error-producing completion phase, so a schema with enough shadowed annotations filled the default 100-issue budget with warnings and stored none of the errors explaining why it failed to load.
- **Behavior change — `E_PROPERTY_CONFLICT` deduplicated per conflict, with complete member pointers.** A property-inheritance conflict is now reported **once per conflict per affected type**, and re-detections through ancestors that merely carry the property forward no longer repeat the diagnostic (v0.8.0 emitted one per carrying ancestor). Each diagnostic now carries **related spans naming every declaration involved** — the full set that merged into the surviving definition, plus every declaration on the conflicting side — so one report never hides a declaration the fix must touch. The message format, primary span, code, and severity are unchanged, but the **declaration the message names on the surviving side is now the one that actually survived the merge**, which differs from v0.8.0 wherever a narrower declaration later took over as survivor. For a given schema the count is deterministic and never exceeds v0.8.0's. Scope and bounds:
  - The per-descendant repetition is retained: each affected subtype re-detects and reports the clash independently, so the failure surfaces at every type it breaks.
  - Grouping is first-fit, so with three or more mutually-tangled same-name declarations the report count depends on `extends`-clause order: deterministic for a given schema, but a permutation can group the same declarations differently and report a different number. Every grouping is sound either way — each report names a genuinely unmergeable pair, and no report ever absorbs a conflict incompatible with the one it names — so the order affects how finely conflicts are split, never whether one is reported.
  - **This affects schemas using no annotations at all** — any load failing on property-inheritance conflicts can report fewer diagnostics than v0.8.0, each carrying more location detail. Loads that pass are byte-identical; the change is confined to loads that already fail.
- **Behavior change — `E_RELATION_COLLISION` deduplicated per collision, with complete rival pointers.** Matching the property-conflict change above: a relation collision is reported **once per collision per affected type**, so ancestors that merely carry the relation forward no longer repeat it (v0.8.0 emitted one per carrying ancestor), and two ancestors declaring **structurally identical rivals** now draw one diagnostic rather than one each — a single edit to the surviving declaration resolves both. Each diagnostic gains **related spans naming the surviving declaration and every rival**, so the collapse never hides one. Rivals that are not structurally equal remain separate diagnostics. Message format, primary span, code, and severity are unchanged, and this affects only loads that already fail.
- **Breaking schema-loading tightening — a property annotation must be on its property's line.** `@name` decorators are property-**trailing** and the grammar does not treat line breaks as significant, so an annotation written on its own line binds to the property **above** it — while a reader coming from a prefix-decorator language (Python, TypeScript, Java) means the property **below**. Nothing distinguished the two readings: the schema loaded clean and the wrong property carried the marker into the emitted store DDL, so `@index` intended for one column indexed another and `yammm neo4j diff` reported the intended index as missing. Such an annotation is now `E_INVALID_ANNOTATION`, naming the property it actually attaches to and pointing at `@@name` for a type-level annotation. Same-line annotations — one or several — are unaffected, which is every form `yammm fmt` produces. Justified under the amended rule (a): the newly-rejected shape is enumerated here, and it never meant what it appeared to mean.
- **Behavior change — `E_PROPERTY_CONFLICT` / `E_RELATION_COLLISION` omit related locations that have no span.** A related entry without a location rendered as a bare `note:` line pointing nowhere — one per member, so a multi-member clash produced a stack of identical, information-free lines — while the LSP dropped such entries entirely, leaving the two surfaces disagreeing about the diagnostic's content. They are now omitted at the source. Affects only `schema.Builder`-constructed schemas, which carry no spans.
- **Bug fix — `Annotation` identity is injective across the name/argument boundary.** The internal identity key that backs duplicate detection and inherited-annotation dedup did not delimit the annotation name from the first argument's encoding, so a name spelled to imitate that encoding collided with an unrelated annotation — reporting a genuine annotation as a duplicate and, on a subtype, letting only one of two distinct composite indexes survive into the merged view. Reachable only through `TypeBuilder.WithTypeAnnotation` / `WithPropertyAnnotation`, which take the name as a plain string; the DSL grammar cannot spell such a name.
- **Bug fix — a diagnostic echoing a quoted annotation argument keeps the source's quote style.** The yammm lexer accepts both `'` and `"`, but the echo re-quoted through `strconv`, so a single-quoted argument was reported back to the user in double quotes.
- **Bug fix — a rejected property re-declaration no longer suppresses annotations for its subtypes.** A re-declaration that drew `E_PROPERTY_CONFLICT` still recorded its annotation drop, so every subtype derived an `E_INVALID_ANNOTATION` disagreement from a declaration the same load had already rejected — telling the user to edit the subtype when the only real fix was at the rejected declaration.
- **Behavior change — `schema.Constraint.Equal` is now reflexive for unresolvable alias chains.** An `AliasConstraint` whose chain does not bottom out in a terminal constraint (an unresolvable datatype, or a cycle) previously compared **unequal to itself**, because equality could not be decided structurally and the undecidable case returned false unconditionally. Such aliases now compare equal when they reference the same datatype — which makes `Equal` reflexive, as every caller assumes — while aliases naming *different* unresolvable datatypes stay unequal, preserving the "cannot determine" policy. Reachable through `schema.Builder`, which accepts an alias-of-alias datatype the DSL grammar cannot express; there, inheritance merging previously reported a property as conflicting with **its own declaration** (`from A and A`), once per carrying ancestor. Schemas whose datatypes all resolve are unaffected, so no schema that loaded clean at v0.8.0 changes behavior.
- **Formatter and editor tooling** — `yammm fmt` (and the LSP's formatting) handle annotation spacing: no space after the `@` / `@@` sigil, and none between an annotation name and its argument list (decided from token-stream state, since that same name-then-`(` pair is a relation multiplicity elsewhere and must keep its space). A line beginning with a sigil is treated as its own declaration rather than a wrapped continuation of the line above. The LSP adds annotation-name and argument completions plus registry-backed hover, and the VS Code grammar highlights the sigils. Because annotation text could not previously parse, **no previously-valid schema formats differently**. Outside the formally-versioned surfaces; noted for completeness.
- **No hash or wire migration.** Annotations are deliberately excluded from `schema.StructuralHash` (`StructuralHashVersion` stays `1`): they drive downstream store DDL and write shape, not what instance data is valid. A schema that gains its first annotation therefore hashes identically to v0.8.0, so every persisted `.ys` snapshot header hash, every snapshot cross-check, and every `gogen` `SchemaHash` constant stays valid.

### Instance-layer edge validation

- **Breaking schema-loading tightening — edge-property datatype references now validated at load.** Association edge properties join the resolution and validation coverage type properties have had since v0.7.0. Three previously-silently-loading schema shapes are now rejected:
  1. An edge property typed by an **undeclared datatype** (`tag Mystery` with no `type Mystery = ...`) — now `E_UNKNOWN_TYPE` at load (previously loaded silently; the v0.7.0 unknown-property-datatype tightening did not reach edge properties).
  2. An edge property whose datatype alias resolves to **Vector** (`type Emb = Vector [3]` + edge property `e Emb`) — now `E_INVALID_CONSTRAINT`, closing the alias evasion of the Vector-on-edge ban (the direct form `e Vector [3]` was already rejected).
  3. An edge property whose datatype alias resolves to **List** (`type Lst = List <String>` + edge property `l Lst`) — now `E_LIST_ON_EDGE`, closing the alias evasion of the List-on-edge ban (the direct form was already rejected).
  Justified under the amended rule (a): the known consumer set declares no such shapes (grep-verified), and each newly-rejected shape is enumerated above.
- **Panic fix — `schema.StructuralHash` on datatype-typed edge properties.** Hashing a schema whose association declared a DataType-typed edge property panicked (`hashConstraint` reached the unresolved alias), crashing every hashing surface: `snapshot.Marshal` (`yammm snapshot save`), the snapshot decoder's schema-hash cross-check, `snapshot.SchemaHashMatches`, `gogen.Marshal` (`yammm gen --to go`), and `schema.Registry` re-registration. All now work. **No hash-migration concern:** affected schemas previously panicked before producing a hash, so no persisted hash, snapshot, or generated artifact changes meaning; schemas without datatype-typed edge properties hash identically to v0.8.0.
- **Validation loosening — datatype-typed edge-property values now validate.** The instance layer previously rejected every value of such a property (`unresolved alias constraint`); values now check and coerce against the resolved underlying constraint, exactly like datatype-typed type properties.
- **Validation loosening — relations declared on imported types and inherited cross-schema now validate.** The instance layer resolves association and composition targets by the completion-recorded absolute identity (`Relation.TargetID`) instead of re-resolving the declared target name entry-relatively. Previously-rejected valid data now validates: edges on imported types whose target is qualified by the declaring schema's own alias (`E_INSTANCE_TYPE_NOT_FOUND` before), compositions on imported types (owner-name lookup failure before), and both member kinds inherited by an entry-schema type from a cross-schema parent. `instance.SchemaBuilder` (`EdgeTo`/`EdgeToWith`/`Composed`) gains the same reach. The public string-tag contracts of `Validate`/`ValidateOne`/`ValidateForComposition` are unchanged (entry-relative, as documented).
- **Data-validation tightening — cross-schema name shadowing no longer misvalidates edge data.** When an entry schema declares a type whose bare name shadows the declaring schema's target of an imported type's relation, the FK block was previously validated against the *entry's* shadowing type: correct-keyed data was falsely rejected and wrong-keyed data **falsely accepted** (an integrity hole caught only later, at graph resolution, blamed elsewhere). Wrong-keyed edge data that previously passed per-file validation (`yammm check`, `instance.Validate*`) is now rejected with the FK diagnostics of the true target; the composition duplicate-child-PK check likewise now runs against the true child type instead of being silently skipped on a shadowed or unresolvable name.
- **Additive API surface (`schema`)** — `Schema.Closure() []*Schema` (the schema plus its transitive import closure: breadth-first over imports in declaration order, deduplicated by SourceID, deterministic, defensively copied) and `Schema.TypeByID(TypeID) (*Type, bool)` (closure-wide lookup of the absolute type identities completion records). Both lazily computed and cached; safe for concurrent use. The three generator adapters' formerly-private closure walks (gogen, jschema, markdown) now consume `Closure()` — an internal consolidation with byte-identical generated output — and the instance layer consumes `TypeByID`. Justified under the pre-1.0 "additive API changes" rule.

The `.ys` wire format is unchanged at v0.9.0 (header `version` stays `2`), and no annotation state is persisted to it. Deferred-resolution behavior is preserved: a registry-less `schema.Builder` schema whose cross-schema relation target was never resolved (zero `TargetID`) falls back to the prior syntactic resolution path and its not-found error.

One bug fix in `adapter/neo4j` plus the additive diagnostic code that announces it, and one internal allocation fix in `instance`. No exported symbol changes signature, no documented behavior is tightened, and the `.ys` wire format is unchanged at `version: 2` — patch tier under the pre-1.0 patch rule, whose additive-API clause permits the new code and whose internal-refactor clause permits the `instance` change.

- **Bug fix — `WithNodeKeyConstraints(true)` under `WithEdition(Community)` emitted no primary-key constraint at all.** NODE KEY is Enterprise-only. The emitter chose the kind from `nodeKeyConstraints` alone, the edition filter then discarded it as a kind Community cannot declare, and the primary key's NOT NULL had already been skipped on the assumption the NODE KEY covered it — so the type's primary key was left with **no constraint whatsoever**. Enterprise behavior is unchanged. ## v0.10.0 under this policy

The fulltext-index annotation pair (`@fulltext` / `@@fulltext`), one diff behavior change it deliberately causes, binary version observability, and the version-lockstep release policy. Minor tier: the DSL and API surface is additive, and the behavior change is a tightening enumerated below. The `.ys` wire format is unchanged at `version: 2`, and — as with v0.9.0 — annotations stay excluded from `StructuralHash`, so a schema gaining its first `@fulltext` hashes identically.

- **Additive DSL surface — `@fulltext` (property) and `@@fulltext(p1, p2, …)` (type).** Two new entries in the blessed annotation registry; the grammar was already generic over annotation names, so no previously-valid schema changes meaning and no grammar regeneration was needed. Eligibility is the text subset of the range-indexable scalars — `String`, `Pattern`, `Enum` — with UUID deliberately excluded (an opaque identifier, not tokenized text). Primary keys are allowed for both placements with no redundancy rule: a uniqueness constraint's backing index is a range index and cannot serve fulltext queries, so the `@index` sole-key rule does not transfer. `@@fulltext` rejects literal arguments; that rejection reserves a trailing string literal as the additive extension slot for a future analyzer option. Editor tooling (completion, hover) picks the entries up through `schema.AnnotationSpecs()` with no LSP-side surface change.

- **Additive adapter surface (`adapter/neo4j`)** — `IndexKind` gains `IndexFulltext`; emission renders `CREATE FULLTEXT INDEX <name> IF NOT EXISTS FOR (n:Label) ON EACH [n.p1, …]` with the `{label}_{props}_fulltext_idx` naming shape; `DiffIndexes` classifies `FULLTEXT` rows through the same three-phase pairing as range and vector, so a hand-named remote fulltext index whose (label, kind, properties) equal a declaration pairs by identity and reads as a Match under its legacy name. Fulltext indexes emit for both editions. Analyzer configuration is a **documented known limit**: the schema cannot declare one, no `OPTIONS` clause is emitted, and the diff does not compare it — a remote fulltext index with a custom analyzer but matching (label, properties) is a Match.

- **The behavior change — the fulltext declarability flip.** Through v0.9.1 an owned `FULLTEXT` row was Excluded from the index diff; it is now a declarable kind, so an owned, *undeclared*, single-label fulltext row classifies as a **Drop**. Consequence: `yammm neo4j diff` (indexes are compared by default; `--indexes=false` opts out) against a database carrying operator-created fulltext indexes on owned labels flips from exit 0 to exit 1 — exactly the definition-drift authority the feature exists to provide. Downstream consumers migrating a hand-maintained fulltext registry must therefore adopt atomically: bump and annotate in one change, or every registry-created fulltext index reads as an undeclared Drop. **Multi-label** fulltext rows (`FOR (n:A|B)`) — a shape no per-type annotation can declare — stay out of declarability, identity pairing, and the definition-blocker map (they are counted in `Excluded`; the server creates a single-label declaration beside them), while their names still block every CREATE.

- **Version observability (`cmd/yammm`, `cmd/yammm-lsp`).** Both binaries now fall back from the ldflags-injected version to `debug.ReadBuildInfo`'s main-module version, so a plain `go install github.com/simon-lentz/yammm/cmd/...@vX.Y.Z` binary self-reports its tag instead of `dev`. Behavioral but strictly informative: only the `--version` output (and the LSP's logged version) changes, and only for builds that previously reported `dev` while knowing better. `(devel)` and versionless builds keep reporting `dev`.

- **Release policy — version lockstep, ratified with this release.** The library tag, both released binaries, the Claude Code plugin (`claude-plugin/.claude-plugin/plugin.json`), and the VS Code extension (`lsp/editors/vscode/package.json`) carry ONE version from v0.10.0 on; the plugin's `check-env.sh` compares each binary's reported version against the plugin's and warns (never blocks) on mismatch in either direction. An independent version bump of the plugin or the extension is barred — the plugin bump silently breaks that comparison's semantics, and the extension bump would claim a server the package does not carry. The extension participates because its marketplace VSIX is not just grammar files: the publish workflow builds a per-platform `yammm-lsp` into every package, and the extension prefers that bundled server over a PATH install whenever `yammm.lsp.serverPath` is unset — so a marketplace republish is what keeps marketplace installs' language server current, and the extension version states which server the package carries. **The release's definition of done includes the tooling ship**: the release is complete only when `yammm-lsp` is released at the same tag and a reinstalled binary verifiably reports it — a stale LSP actively rejects the new grammar as `E_SYNTAX`, which is the observed failure mode this requirement closes — and when the VS Code extension is republished from the release tag, so the bundled server is built at that tag rather than left at the previous release's grammar.

The DSL parser is now hand-written over `participle/v2`; the generated ANTLR parser, its grammar, and the `github.com/antlr4-go/antlr/v4` dependency are deleted. Minor tier on two independent grounds: the release removes three exported symbols (enumerated below under conditions (a)–(c) of the pre-1.0 subtractive rule), and it changes user-visible behavior in the seven ways enumerated below. The `.ys` wire format is unchanged at `version: 2`, and no schema that parsed under v0.10.0 fails to parse under v0.11.0 — the parity bar the migration was measured against.

- **Removed exported symbols — the rune-to-byte conversion.** Three symbols leave: the interface `location.RuneOffsetConverter`; the method `RuneToByteOffset` on the exported interface `schema.SourceRegistry`; and the method `RuneToByteOffset` on `*schema.Sources`. The unexported `(*source.Registry).RuneToByteOffset` behind them goes with them. The conversion existed because ANTLR reports token positions in runes; `internal/parse` reads bytes, so spans are byte-native end to end and nothing converts. Condition (a) is met by grep: no production caller anywhere in this module (`lsp/` included), and zero external Go references across the known consumer set. Implementors of `schema.SourceRegistry` need no change (an interface losing a method only loosens its contract); callers that invoked `Sources.RuneToByteOffset` directly must drop the call. **The `runeOffsets` index itself stays** — `internal/source` computes every `location.Position`'s 1-based rune column from it, and that is unchanged.

- **A shipped crash is fixed.** `schema.LoadString` and `LoadSourcesWithEntry` no longer panic on an invariant expression ending in a pipeline arrow at end of input (`type A{!00->`). Under v0.10.0 this is a nil dereference in the expression visitor, and it takes the LSP down with the editor session. Pinned by three `FuzzLoadString` seeds that panic on the pre-swap tree.

- **An annotation written with an empty argument list draws its arity diagnostic.** `@vector()` and `@@index()` now report `E_INVALID_ANNOTATION` beside the syntax error, where the ANTLR path suppressed it. `@index()` does not, because it legitimately takes no arguments.

- **A written reserved import alias loses its `E_INVALID_ALIAS`.** The token-anchored `E_SYNTAX` is now the only diagnostic on that construct, and the import survives with a derived alias — so it reaches the loader, which adds `E_IMPORT_NOT_ALLOWED` under `LoadString`.

- **A string literal holding invalid UTF-8 keeps its bytes** rather than having them rewritten to U+FFFD.

- **A header that does not parse reports one fatal, not two issues.** The spanless `missing schema name` diagnostic is gone; the token-anchored one survives.

- **An inherited, shadowed, zero-argument `@index()` now draws `W_ANNOTATION_SHADOWED`** — the re-statement advisory it did not draw before, because the shadow check skipped it on a flag the ANTLR path set and this one does not.

- **Diagnostic wording — syntax messages name their location uniformly.** Every location phrase now reads `in <article> <construct>` across a closed seven-phrase vocabulary (`in the schema header`, `in an import declaration`, `in a declaration`, `in a type body`, `in an expression`, `in an expression list`, and the end-of-input phrase). Five strings changed; `unexpected end of input in type body` and `unexpected token %q in expression` are the two a schema in the wild is most likely to have logged. Separately, grammar node names no longer reach user-facing text: v0.10.0 could print an expected-token list naming an implementation identifier (`expected UcWordNode`), and the new parser emits no expected-set at all. Consumers matching on diagnostic **codes** are unaffected; consumers matching on message text are not.

- **Recovery shape on malformed input.** Measured end-to-end over the 52-case malformed casebook, first-error quality is level with v0.10.0 (**41/52** first hits matched on both sides, with four cases losing their first hit and four gaining one) and no case loses a declaration that v0.10.0 kept. Recall is 0.88 against 1.00: nine planted defects are reported by a same-line sibling diagnostic rather than at the defect itself, four of them artifacts of ANTLR tree holes. Both frozen golden sets — the 136-fixture valid corpus and the 52-case casebook, with its per-case declaration inventory — ship in `internal/parse/testdata/` as the tracked successors to the retired differential.

- **Cost — `schema.LoadString` is 2.75×–3.27× slower.** Measured across both corpora and both instruments; the largest tracked fixture goes 1.157 ms → 3.788 ms. The parse phase is about 65% of a load, so the end-to-end ratio is dominated by the parser and not by anything downstream. Accepted deliberately with the numbers in hand: the alternative is an optimization project, and the absolute figures stay inside the ratified 10 ms largest-fixture line. Load-heavy consumers should measure rather than assume.

- **Dependency — `github.com/antlr4-go/antlr/v4` is dropped** and does not appear in any consumer's module graph through yammm. `github.com/alecthomas/participle/v2` v2.1.4 is a direct dependency. Java and the ANTLR jar are no longer needed to build or develop yammm, and `make generate-grammars` is gone — the parser is source, not generated output.

The single external consumer absorbs the first two breaks on its own schedule (compile-time via the re-key, read-time via the wire) and is measured unaffected by the third and the fourth.

- **`TypeOf` reports the DSL type vocabulary.** The value was the Go `%T` string (`"int64"`, `"float64"`, `"bool"`, `"[]interface {}"`, and `"immutable.Slice"` for a list-valued property — the same value could report two names depending on how it arrived). It is now a closed vocabulary: `"nil"`, `"boolean"`, `"integer"`, `"float"`, `"string"`, `"list"`, `"map"`, `"pattern"`, `"timestamp"`, `"uuid"`, with `"unknown"` for any value outside it. The name comes from the **value**, not the declared property type: a `Timestamp`, `Date` or `UUID` property holding a string yields `"string"`, and only a `Timestamp` holding a Go `time.Time` yields `"timestamp"` or a `UUID` holding a `uuid.UUID` yields `"uuid"`. A `uuid.UUID` is `[16]byte`, so before `"uuid"` joined the vocabulary it reached the classifier's array arm and reported as `"list"`. Naming the declared type would require the constraint at the builtin, which the signature does not carry; the limit is documented in SPEC rather than engineered away. Any invariant comparing `TypeOf` output against a Go type name changes result. In-repo and known-consumer usage of `TypeOf` was zero at the decision; the vocabulary is enumerated in SPEC and pinned by the tracked contract corpus.

- **Extra bracket arguments draw an evaluation error.** `expr[a, b]` previously evaluated as `expr[a]`, silently discarding — and never evaluating — every argument after the first, while SPEC documented a range slice that did not exist. It now draws `E_EVAL_ERROR` (`slice access accepts exactly one index`). A tightening: no valid program can depend on the discard. Single-index behavior is unchanged, including out-of-range evaluating to `nil`.

- **The else-less ternary is rejected at load time.** `cond ? { x }` previously parsed and then drew `E_EVAL_ERROR` on every evaluation — both branches, always, since the evaluator requires three operands. The missing `:` is now `E_SYNTAX` (`expected ':' and an else branch in a conditional`) at schema load. A schema carrying the form stops loading, but no working schema breaks: the form could never evaluate.

- **String literals resolve the documented escape vocabulary.** The unquoter previously rebuilt every literal as a Go double-quoted string and delegated to `strconv.Unquote`, so three spellings SPEC has always documented drew `E_SYNTAX`: an unescaped `"` inside a single-quoted literal (`'a"b'`), the `\'` escape in either quote style (leaving no way at all to write an apostrophe in a single-quoted literal), and bare `\0`. A hand-rolled unquoter now resolves exactly the lexer's escape set (`\b \t \n \f \r \0 \xHH \uHHHH \" \' \\`), so those spellings load. Mostly a loosening — previously-erroring input now loads — with **one value delta**: `\0` is no longer a Go octal prefix, so a literal like `"\012"` previously resolved to the single byte U+000A and now resolves to U+0000 followed by `12`. Malformed escapes (`\x` without two hex digits, `\u` without four, surrogate code points) still draw the same diagnostic with the same message text at every site: `unquote string: invalid syntax` as the cause at the schema-name, import-path, enum, pattern, timestamp and annotation sites, and `invalid string literal: invalid syntax` at the expression site, which supplies its own context and so reports the cause without the shared prefix. Consumers matching diagnostic text on the error path see no change. Reaches every unquote site: schema names, import paths, enum values, pattern values, timestamp formats, annotation string arguments, **and invariant-expression string literals**. The expression site was the last to route through the shared unquoter and had the sharpest symptom: it delegated to `strconv.Unquote` on the raw token, which reads a single-quoted literal as a Go *rune* literal, so **no single-quoted string of more than one character could be used in any invariant** — `! "m" name == 'abc'` drew `E_INVALID_INVARIANT`, as did the `\'` escape and bare `\0` there. Note the code at that site is `E_INVALID_INVARIANT`, not `E_SYNTAX`. **Invalid UTF-8** now resolves as `strconv.Unquote` resolved it — each bad byte becomes U+FFFD — so `\0` remains the only value delta.

- **Schema-aware float emission — `.ys` whole floats gain decimal form.** `snapshot.Marshal` now emits every value under a `KindFloat` constraint — node, edge, unresolved-edge, composed-child, and duplicate-section properties, `List` elements (aliases resolved at every level), and `Vector` elements — in a form carrying a float indicator: `float64(1860000)` writes as `1860000.0` where it previously wrote `1860000` and narrowed to `int64` on the next load. Behavioral rather than structural in its own right — it changes no field, and `immutable.NormalizeNumber` has always classified decimal forms as float — though it ships inside the `version: 3` wire replacement below. **Healing**: an `int64` already narrowed by a prior round trip re-emits in decimal form on its next Marshal. Healing turns on **exact convertibility**, not magnitude — an integer heals when `float64(n)` converts back to `n` exactly, so `1e18` and every power of two beyond 2^53 heal where a plain 2^53 bound stranded them, while `MaxInt64` and `2^53+1` still pass through. **Every numeric value** a caller can place under a float-bearing constraint is covered, not only `float64` and `int64`. `float32`, every sized int and uint, named types over them, and `encoding/json.Number` all reach the emitter and must not narrow. They arrive through `graph.RebuildSnapshot` or a test helper, and a `json.Number` also arrives from a caller who decoded with `UseNumber` or from a value `immutable.NormalizeValue` left unconverted past its depth cap. A `json.Number` is classified by `immutable.NormalizeNumber`, the rule the reader itself applies, so one literal cannot mean a float on the way out and an `int64` on the way back in. A literal neither parser accepts passes through untouched, because inventing a value for it would write data the document never carried. A `float32` emits the shortest form that reads back as the same `float32`: `float32(0.1)` writes `0.1`, where widening to `float64` and formatting at 64-bit width spends 17 significant digits describing 32 bits of value. Vector embeddings are the natural `float32` shape, so that width is kept at every element of every embedding. Marshal output is a fixpoint — `Marshal(Load(Marshal(x)))` is byte-identical to `Marshal(x)`; under the v3 wire below the property holds structurally, because a type holding no root instances survives the round trip as an empty instances group. `snapshottest.DiffSnapshots` drops its mixed int64/float64 tolerance: round trips compare exactly, dynamic type included, with one deliberate exception — a `float32` compares equal to the `float64` its 32-bit shortest wire form parses to, because `Load` materializes dynamic numeric values as `int64` and `float64` only and the wire carries value fidelity, not width; converting the loaded `float64` back to `float32` returns the original. The duplicates section compares full instance trees plus each record's conflict, parent and relation coordinates rather than bare identities. Byte movement: integrity hashes of float-bearing documents change on re-marshal; `UpdateMetadata` keeps an int-shaped body verbatim while `Marshal(Load(x))` heals it — the one deliberate divergence between those two paths, recorded in the wire contract. Emission is unconditional; there is no opt-out flag, because a flag would preserve the ambiguity the change removes. A NaN or Inf under a float-bearing constraint errors from the wire-value marshaler rather than from `encoding/json` directly, so the message differs in prefix; validation rejects both at `coerceFloat`, so only a caller-assembled snapshot reaches it. A `Vector` or `List` position is reached through **any slice or array**, not `[]any` alone, so a caller-assembled `[]float32` or `[3]float64` reaches the emitter rather than passing through int-shaped. This does not change how a `[]byte` renders, and no release ever wrote one as a base64 string: `immutable.WrapProperties` wraps every slice as an `immutable.Slice`, so `Properties.Clone` hands `Marshal` a `[]any` whatever the caller stored, and `encoding/json` never sees the `[]byte` that would have triggered its base64 encoder.

- **Additive: `schema.TagForm`.** `schema.TagForm(s *Schema, id TypeID) string` renders a type identity as its DSL tag form — bare for a local type, alias-qualified for a directly imported one. It is the single implementation of a rule that previously had drifting private copies, and it is what callers use wherever output needs a name rather than an identity: the adapter writers, the CLI exporter, and `Load` itself (which derives every `Instance.TypeName()` from the resolved identity) all render names through it.

- **Importing a snapshot keeps every instance of a transitively imported type.** `graph.NewFromSnapshot` and `graph.NewBatchAssemblerFromSnapshot` filed instances by resolving the tag form, which misses a bare transitive name — and the miss was a silent `continue` that **dropped every instance of the type**. Instances are now filed by the identity each one carries, which the re-keyed `Snapshot` hands them directly. The path was unreachable while `Load` rejected such documents outright; fixing the load is what makes it reachable. Also: `E_UNRESOLVED_REQUIRED`'s `json_field` detail is populated for imported source types, where a local-name-only lookup left it empty for exactly the types a cross-schema document holds.

- **BREAKING — `graph.Snapshot` is keyed by type identity, not by type name.** A type name is a *rendering* of `schema.TypeID`: bare for a local type, alias-qualified for a directly imported one. It cannot name a type reachable only through an intermediate import — that renders bare — and it renders two same-named types in different schemas identically. Keying by it merged them: `Graph.Snapshot()` overwrote one group of instances with the other **before `Marshal` ran**, so a lossless wire would have described data the snapshot no longer held. Every position that must denote a type exactly now takes an identity. **Changed signatures**: `Snapshot.Types() []schema.TypeID`, `Snapshot.InstancesOf(schema.TypeID)`, `Snapshot.InstanceByKey(schema.TypeID, string)`. `Snapshot.AllInstances()` is unchanged in signature. **Changed field types**: `SnapshotParts.Types` and `SnapshotParts.Instances`; `EdgeParts.SourceType` / `TargetType`; `DuplicateParts.Type`; `UnresolvedParts.SourceType` / `TargetType`; and the public `UnresolvedEdge.TargetType`. That last one is not a display field — `graph.NewFromSnapshot` reads it back to build the pending-edge key that later resolves an arriving target, so a name there would be re-resolved and could bind to the wrong type. Callers needing a name for output take it from the new `schema.TagForm`; the three adapter writers and the CLI exporter do exactly that. `Types()` sorts on `TypeID.String()` (schema path, then name) rather than on the rendered name, which is the order the v3 types table below carries. Permitted under the amended pre-1.0 rule (a): the single external consumer pins an older release and migrates on its own schedule.

- **BREAKING — the `.ys` wire format is replaced: `version: 3` is the only version, written and read.** v2 carried type identity as a lossy tag-form *name* at every position — the `types` array, the instances-map keys, `edge.target_type`, `duplicate.type`, the unresolved record's source and target — plus an *optional* per-instance `type_id` object written only where three hand-maintained omission predicates said the name would not recover it. A name cannot express a transitively imported type and renders two same-named types in different schemas identically, and four consecutive review rounds found defects in the machinery built to invert it. v3 carries identity **once, losslessly**, and v0.12.0 reads nothing else:

  - **`types` is a table of `{"schema_path", "name"}` rows** — the document's denotation set: every type the document references anywhere, in identity order. There is no `tag` column. A rendered name is derived from the resolved identity at load time, so the wire carries no name that could disagree with the identity beside it.
  - **`instances` is a list of `{"type": <row>, "items": [...]}` groups.** A group present with an empty `items` array means the snapshot holds the type with no instances; an absent group means the snapshot does not hold the type; two groups claiming one row are malformed. The byte fixpoint above holds structurally on this shape — a type denoted only as a reference target survives the round trip.
  - **Every other type reference is a nullable table-row index**: composed children (stated at every non-root position), `edge.target_type`, the duplicate record's type, its conflict's, its parent's, and the unresolved record's `source_type` and `target_type`. A null, absent, or out-of-range reference draws an Error (`E_SNAPSHOT_MALFORMED`) and never binds to row 0. The per-instance `type_id` object is gone — a v3 writer omits nothing, so the omission-predicate class is deleted rather than corrected again.
  - **The four top-level keys are exactly four, in order, each once, none null.** `yammm_snapshot`, `types`, `instances`, `diagnostics`. The reader previously enforced only that `yammm_snapshot` came first and that `types` existed; a document missing `instances` or `diagnostics` loaded as a valid empty snapshot, a repeated key was silently merged by the JSON decoder, a fifth key was skipped, and the stated order was not checked at all. Every departure now draws an Error (`E_SNAPSHOT_MALFORMED`) naming what was wrong. **The rule has one implementation, and every surface holding the whole document runs it** — `Load`, `Verify`, `Info`, `HeaderOnly` and `UpdateMetadata`. `HeaderOnlyRead` and `ScanDir` do not: they read through a reader capped at `MaxHeaderSize` and never hold the body, so they cannot see the document's shape and say so on their own godoc rather than accepting it by omission. That last one is the point: `UpdateMetadata` emits a fresh integrity hash, so a document it accepts and no reader accepts is a malformed document that passes verification. `Marshal` has always written all four keys in order, so no yammm-written document is affected; the tightening reaches truncated and hand-edited files only.
  - **`Info` runs the same structural validation as `Load` and `Verify`.** It decoded the whole body already and validated almost none of it, so a document those two refused as malformed — two instances entries claiming one table row, a reference to a row that does not exist — `Info` summarised clean with silently short counts. The three surfaces now classify every document identically and differ only in what they build afterwards. `Info` still returns a summary beside Error-severity diagnostics; read the result before the summary.
  - **An unresolved record's reason binds its payload.** The reason must be one of `target_missing`, `absent` or `empty`, and the two that describe a reference which never had a target must carry no target key and no properties — the contract `graph.UnresolvedEdge` documents and the writer has always met. A record breaking either rule previously loaded, materialised a value the type documents as always empty, and lost it again on the next write.
  - **`Marshal` reports the composed-nesting bound as the reader does.** A snapshot nested deeper than the reader accepts returns Error `E_SNAPSHOT_DEPTH_EXCEEDED` rather than Fatal `E_INTERNAL`, so the same condition carries the same code and severity from both sides.
  - **Table resolution is strict.** A row the import closure does not declare draws an Error (`E_SNAPSHOT_UNKNOWN_TYPE`) with no name fallback: a v3 document was written by a writer that resolved every identity at write time, so an unresolvable row means the schema moved, and a diagnostic the consumer can act on beats a silent rebinding. Two rows carrying one identity are malformed.
  - **Every duplicate record carries a `conflict: {type, key}` block** naming the instance it collided with, beside the parent coordinates described in the additive entry below. A keyless slot occupant is addressed with `"key": null` and resolves through the parent slot alone. A composed duplicate's parent coordinates must name a root instance; coordinates that do not draw `E_SNAPSHOT_DANGLING_REFERENCE` from `Load` and `Verify` alike.
  - **One reader.** `Load`, `Verify` and `Info` share one pipeline: one structural walk feeds one index, `Load` and `Verify` agree on every document, and materialization begins only after every check has passed — a document that draws an Error returns no snapshot.
  - **`MinReadableVersion` is 3** (v0.11.0: 1), and the accept range is exactly `[3, 3]`. A v1 or v2 document draws an Error (`E_SNAPSHOT_UNSUPPORTED_VERSION`) on every read surface — `Load`, `Verify`, `Info`, `HeaderOnly`, `HeaderOnlyRead`, and `UpdateMetadata`. **There is no migration path**: yammm supports one wire version at a time, and pre-1.0 compatibility surface is dropped rather than maintained. v3 shipped in no earlier release, so only v0.12.0 writes it; a consumer holding v2 documents regenerates them from source data or reads them with an older yammm. An older reader (v0.11.0 and earlier) rejects a v3 document cleanly through its unknown-version path.
  - **Byte movement is total.** Every document changes shape and every integrity hash changes — inherent to a format replacement. Cross-schema documents shrink substantially: one table row replaces every per-instance `type_id` object naming the same identity.

The resolution rule is now uniform and address-following: a root conflict resolves through the instance index at its stated address; a composed conflict resolves through the parent's relation slot, where a stated key selects the sibling whose type and key both match and an empty key addresses the slot's sole occupant. `graph.RebuildSnapshot` also rejects a zero `schema.TypeID` at every parts position with a Fatal `E_INTERNAL` naming the position and key — identity is total at the graph boundary, so caller-assembled parts meet the same rule `Load`-produced parts do.

- **`UpdateMetadata` preserves the input header's version fields, refuses documents no read path accepts, and returns the warnings it collects.** The metadata fast path rebuilt the header through helpers that wrote the writer's current `version` and `schema_hash_algorithm` constants as literals while reusing the body verbatim, so a header rewrite could relabel a body it did not produce. Both are now parameters: `Marshal` passes the current constants, `UpdateMetadata` passes what it read — a header rewrite is never a migration. Separately, `UpdateMetadata` tested only the error `decodeHeader` returns and never its collected diagnostics, so it accepted shapes every read path refuses — a version outside the accept range (v1 and v2 documents included, under the v3-only surface above), `features: null`, and an unrecognized feature entry. It now returns those diagnostics instead of rewritten bytes, and `UpdateMetadataOrReMarshal`'s `Load` fallback refuses them the same way; the fallback remains available for non-`Marshal`-shaped input the reader accepts. The hash-algorithm mismatch stays a Warning, still passes, and is now returned on the success path instead of being discarded.

- **Indented output nests the body sections by the caller's indent.** `Marshal` passed a hardcoded two-space prefix to the body-section encoders while the header nested by the configured indent, so `WithIndent("\t")` produced a document whose header used tabs and whose `types`, `instances` and `diagnostics` sections used two spaces then tabs. Both are now the caller's indent. Compact output is unaffected; indented output changes bytes and therefore its integrity hash.

- **A registry-less `schema.Builder` rejects dangling qualified references.** A qualified reference (`Extends`, a relation or composition target, or a qualified datatype constraint) whose alias names no resolvable import previously deferred "to link time" when no registry was provided, sealing a schema that silently dropped its supertype, left a zero relation `TargetID`, or kept an unresolved primary-key type — even though no link step exists that could ever resolve it. It now draws `E_UNKNOWN_TYPE` and nils the schema, exactly as the same reference does with a registry present. **Breaking** for any consumer building registry-less schemas with qualified references (none is known; the state was production-unreachable — the single external consumer builds exclusively via `Load`). This reverses the registry-less half of the v0.7.0 strictness note's second `Builder` carve-out; the declared-but-failed-import deferral (the root cause already reported) is unchanged. Consequence: a sealed schema carrying a dangling or deferred reference is no longer obtainable through any public entry point, so the downstream defensive arms (the adapter's emission-time index re-checks, the instance layer's entry-relative target fallback) become pure defense in depth — their codes (`E_NEO4J_UNKNOWN_PROPERTY`, `E_NEO4J_INVALID_INDEX_TARGET` via this route, `E_INSTANCE_TYPE_NOT_FOUND` via the fallback) stay registered and the code stays, but no public construction reaches them.

- **Cost — `format.TokenStream` stops lexing the source twice.** The formatter needs both the un-elided token stream and the node tree; it previously ran a full second lex for the stream. An internal single-pass entry point now returns both views from one lex, cutting formatter time by 29% on the tracked fixture corpus and 41% on a 200-type synthetic schema (Apple M2). Both figures are derivable from the committed benchmarks rather than a one-off comparison: the removed work is exactly one `parse.Lex`, so `BenchmarkLexOnlyCorpus` / `BenchmarkLexOnlySynthetic` measure it directly against `BenchmarkTokenStreamCorpus` / `BenchmarkTokenStreamSynthetic`. Output bytes are unchanged — the returned stream is pinned equal to the standalone lexer's over every tracked fixture — so this is purely a performance change on the `yammm fmt` and LSP formatting paths.

- **A `List`-typed property is indexable, and `Len` counts a map.** `expr[i]` handled `[]any` and `string` but not `immutable.Slice` — what `Value.Unwrap` returns for a collection — so indexing any List property was an evaluation error against the SPEC's own Indexing section. `Len` had the mirror gap: a map value is `immutable.Map[string]`, a struct, which its `reflect.Map` arm never matched, so `$self -> Len` errored while `$self -> TypeOf` already answered `"map"`. Both are fixes; no working expression changes meaning. The empty index list `expr[]` keeps drawing an evaluation error, now worded in the same user-facing vocabulary as the two-index case. The List arm bounds-checks in `int64` like its `[]any` and `string` siblings, so an index beyond `int32` range yields `nil` rather than wrapping into range on a 32-bit build — unobservable on every platform this project ships, and relevant only to a consumer building 32-bit.

- **The LSP canonicalises every path the same way.** Four hand-written canonicalisers — in the analyzer and at three workspace sites — differed from each other and from the schema loader's own `makeCanonicalPath`: some resolved symlinks before cleaning, where the loader cleans first, and some skipped making the path absolute. For a path containing `..` across a symlink the two orders land on **different files**, not two spellings of one. All of them now route through a single helper mirroring the loader's order (absolute, then cleaned, then resolved, keeping the cleaned form when resolution fails, which a virtual markdown source and a deleted file both need). User-visible where a workspace root arrived in a form the document paths did not match: the root registered under a path no document matched, so `FindModuleRoot` fell back to the file's own directory. **No client-visible diagnostic misposition was fixed** — an earlier framing of this work claimed one, and driving the real server with the change reverted produced identical, correct columns; what changed is the robustness of the Analyzer's own API and the canonicalisation ordering.

- **SPEC corrections from the contract-freeze pass.** Three false claims corrected — property lookups documented as strict (they are statically checked at load; declared-but-absent evaluates to `nil`), the `expr[start, end]` range slice (never implemented; see the tightening above), and "ordered comparisons evaluate to false for incomparable operands" (supported types are totally ordered by strata) — plus nine documented gaps closed (list `+` concatenation, `Substring`'s one-argument/negative/clamping forms, the empty-collection results table, `Len` on maps, invariant nil-fails/non-bool-errors semantics, NaN-equals-NaN and float-division-by-zero under the total order, cross-form numeric type checks, the two-`/`-per-line regex-lexing note, the timestamp string-order caveat). The executable contract behind the prose is promoted to a tracked corpus (`instance/testdata/contract/`) whose driving tests pin every documented behavior and every error probe's exact diagnostic.

- **Additive: `schema.WithSyntheticRoot`.** `WithSyntheticRoot(root string) LoadOption` makes `LoadSourcesWithEntry` derive in-memory source identities from `root` joined to the source key, so a source keyed `a/b/x.yammm` under `embedded://app` has the identity `embedded://app/a/b/x.yammm` on every machine. Before it, a hermetic load still routed every key through `location.SourceIDFromAbsolutePath`, so `WithSourcesOnly` produced filesystem-derived identities and `LoadString` — which does mint a synthetic identity — sets `disallowImports` unconditionally and can never serve an importing schema. **The root also stands in for the module root**, which is what makes the option work rather than merely compile: two guards run before identity derivation is reached — `loadImports` reports `E_IMPORT_RESOLVE` when the module root is empty and the entry is not file-backed, and `resolveImportToRelative` rejects a module-style import with no module root — and both would otherwise fire on every importing schema. One `loader` predicate now holds that test so the two cannot fork. The option refuses rather than degrades in four cases: an invalid root (empty, or absolute-looking after the trailing slash is trimmed — an absolute-looking root would collide with file-backed identities and break wire dedup silently); a root without `WithSourcesOnly` (an unresolved import would fall back to a sandboxed disk read and mix a file-backed identity into the same closure); a root together with a non-empty `moduleRoot` argument; and the option passed to `Load` or `LoadString`, where it could only ever be a silent no-op. The predicate runs **last**, after the `.ys`, regular-file and `TmpSuffix` rules, so it is consulted for exactly the entries the unfiltered scan would yield and never for a FIFO — `os.Open` on one blocks until a writer appears, which would hang the scan rather than fail it. `ScanCandidate.Info` stats through a symlink, so it describes the file the open will read rather than the link, agreeing with the `FileSize` and `ModTime` the entry will carry; it resolves at most once per candidate and not at all when no predicate asks, and it returns a stat failure rather than a zero `FileInfo`. `ScanDir` and `ScanDirSlice` become one-line delegations to the option forms and are **byte- and syscall-identical** given no options; the two share one option set, on the precedent of `LoadOption` serving both `Load` and `Verify`. **The cost, stated:** a rejected file saves the open, the fstat and the header read; an admitted one pays one extra stat, or none when it is a symlink whose stat the regular-file check already paid for. **The window, stated:** the predicate observes the file before the open while the entry reports it after, so a file rewritten in between reports values the predicate did not see.
- **Record correction: the stated justification for `ScanEntry.ModTime` was wrong.** The field was recorded as unblocking a bespoke directory walk in the sole consumer. It does not, and could not: that walk exists to skip a file *without opening it*, and `ScanDir` opens every file it yields while `scanFile` takes its stat from the already-open handle. The consumer documents the pre-open property on its own option and has a test that fails if a file outside the window is opened, so it is a tested contract there rather than an incidental optimization. The claim was a hypothesis about a consumer treated as a measurement — the failure class the aliveness rule already names — and the pre-open filter above is what the consumer's need actually required. The field ships on its own merit: a scan reported a size but not a modification time, and the same consumer calls `os.Stat` inside a `ScanDir` loop for a size the entry has carried since v0.12.2.

## v0.13.0 under this policy

Minor tier: a behavioural change to how three schema kinds are stored, and one break on the generated-output surface. No exported symbol is removed or re-signatured on the Go API, and the `.ys` wire format is unchanged at `version: 3` — `MinReadableVersion` and `currentVersion` both stay `3`, no field is added and no section moves. Permitted under the pre-1.0 minor rules: the behavioural items under "behavior tightenings" as documented contract changes, and the generated-output removal under that surface's Breaking tier, which is a minor pre-1.0.

The release executes the two defects v1.0 condition 2 dispositioned by decision on 2026-08-19. Both were pre-existing; no release caused either.

### The value-canonicalization family

yammm accepts a range of Go representations for a value and stores one canonical form — `Integer` accepts an `int32` and stores `int64`, `Float` accepts an `int64` and stores `float64`. **Three kinds broke that rule**, in two directions: `Timestamp` and `UUID` accepted two representations and canonicalized at neither end, and `Date` accepted only a string while `adapter/gogen` mapped the kind to `time.Time`, which the validator rejected. One rule now governs all three, computed in one place and applied at every boundary that stores or writes a value.

- **Behavioural: `Timestamp`, `Date` and `UUID` properties store a canonical string.** A `Timestamp` renders through its declared format when it has one and through RFC 3339 with nanoseconds otherwise; a `UUID` through its canonical lowercase hyphenated text; a `Date` through `"2006-01-02"` **in the value's own location**, so an instant at 00:30 `+02:00` is the 19th and the same instant at 22:30 `Z` is the 18th. This is the break a library consumer observes, through `Instance.Properties()`. `snapshot.Load`'s return type is unchanged — it returned a string before and returns one after, which is the same asymmetry closed from the other side.
- **Behavioural, and a widening: a `Date` property accepts a `time.Time`.** The kind rejected the type before, at `CheckValue` as well as at coercion — the check had to widen too, or the coercion arm would never have been reached. `adapter/gogen`'s type mapping is unchanged: `Timestamp` / `Date` → `time.Time` was always what it emitted, and this is what makes the emitted field usable as authored for the first time. A consumer's hand-written `Format("2006-01-02")` conversions become redundant rather than wrong.
- **Behavioural: a non-canonical string normalizes.** The rule parses a string form and re-renders it, so one value reaches one spelling however a caller wrote it. `"…+00:00"` stores as `"…Z"`, `".500Z"` as `".5Z"`, `".000Z"` with the fraction dropped; every UUID spelling `uuid.Parse` accepts — uppercase, brace-wrapped, `urn:uuid:`-prefixed, bare 32-hex — stores as the canonical form. **The UTC offset survives**: an offset records where an observation happened and is data rather than formatting, and normalizing to UTC would discard it and falsify the SPEC sentence that Timestamp comparison is string comparison.
- **Behavioural: a primary key moves when its component normalizes, and only then.** Two classes move: a key under a declared custom layout, because the format it renders through is the one it always should have used; and a key whose component was stored in a non-canonical spelling. **Canonicalizing the Go-native form moves no key** — `computeKeyString` renders a key through `encoding/json`, and both canonical forms are the text `encoding/json` and `uuid.UUID.MarshalText` already produce. Measured for whole-second, sub-second, nanosecond and non-UTC-offset values. Neither moving class exists in the known consumer set, where every primary key is a `String`.
- **Bug fix: a `UUID` primary key no longer splits silently.** One UUID submitted as a `uuid.UUID` and as its uppercase string produced **two instances under two keys with no duplicate reported**. All five spellings now reach one key and one instance.
- **Bug fix: a custom-format `Timestamp` built from a `time.Time` is written in text that satisfies its own declared format.** The check returned on its first line for a `time.Time` and never reached the format check, so the value reached the wire as RFC 3339 — text its own layout rejects. This changes wire bytes for such a value, as a correction.
- **Bug fix: comparison over a `Timestamp` or `UUID` no longer draws `E_EVAL_ERROR` for the Go-native form.** `time.Time` is a struct and `uuid.UUID` is `[16]byte`, so neither reached a comparison stratum and every ordered operator over one was an evaluation error. `in` was worse: it swallows a comparison error, so a `time.Time` was silently absent from a list holding it. **This restores the SPEC sentence naming a map as the only unsupported shape**, which was false. `adapter/json` also stops marshalling a `uuid.UUID` as an array of sixteen numbers.
- **Behavioural: `TypeOf` loses `"timestamp"` and `"uuid"`.** Invariants evaluate on coerced values, so after this release neither is a result anything can produce. Both leave the documented vocabulary; a `Timestamp`, `Date` or `UUID` property yields `"string"`. In-repo usage was measured at zero, and the tracked contract corpus pins neither name.
- **Behavioural: the CSV and JSON writers render a value through its constraint.** Both already iterate every property; the added cost is one type switch per property on a walk that exists. **Including list elements**, which take the element constraint, and **including foreign-key columns**, whose components render through the **target** type's primary-key constraints — the target type differs from the row's own, so the constraint is one hop away rather than absent. Leaving it would have shipped a release where every surface renders canonically except one column. Neither writer touches edge properties; those reach the wire arm and `adapter/neo4j`, which already handle them.
- **Behavioural: `graph.RebuildSnapshot` canonicalizes its parts.** It is the deserialization entry point, so a graph rebuilt from parts now holds what a graph built through validation holds, and the snapshot round trip reaches a fixpoint on the first pass. Primary keys are deliberately untouched: the wire holds canonical text, so a loaded key is already canonical, and rewriting a caller-supplied key would move it in the instance index with every edge endpoint having to move with it.
- **Contract, stated rather than changed: a write arm never fails a write.** The wire arm, both writers and the rebuild arm heal what they can and pass through what they cannot. This is the contract `wireNumeric` has carried since v0.12.0, verbatim in its godoc. Erroring instead would make documents yammm itself wrote unwritable after upgrade — a pre-release document carrying a custom-format `Timestamp` built from a `time.Time` holds text that fails its own layout, and that output is on disk.
- **Behavioural, enumerated: a custom-format `Timestamp` under a lossy layout loses what the layout cannot express, on every path including `adapter/neo4j`, which did not lose it before.** Under `"2006-01-02 15:04:05"` the value `2026-08-19T12:00:00.5+02:00` renders `"2026-08-19 12:00:00"`, which parses back to a different instant. Previously a `time.Time` returned from `adapter/neo4j.Coerce`'s first line untouched, so the loss was confined to the string form. The default RFC 3339 rendering with nanoseconds round-trips exactly, so the loss is confined to declared layouts — and those now draw a warning at schema load.
- **One bypass remains and cannot be closed.** `instance.NewValidInstance` receives no schema, and giving it one is a breaking signature change; its name is the caller's assertion that the value is already valid. `Properties()` on a graph built that way returns what the caller passed, and the wire and writer arms are what catch it downstream.

### Neo4j: offset-bearing timestamps

- **Bug fix: `adapter/neo4j.Coerce` re-renders an offset-only instant into the form the driver can send.** A `time.Time` whose location carries no name — exactly what `time.Parse(time.RFC3339, "…+02:00")` produces, and therefore what `Coerce`'s string arm produced — was rejected by the server with `Illegal epoch adjustment`. The driver selects its wire encoding by the zone **abbreviation**: it sends an offset only when `Zone()` reports `"Offset"`, and otherwise sends `Location().String()` as a time-zone identifier, which for an unnamed location is empty. `Coerce` now expresses such an instant in `time.FixedZone("Offset", …)` — the driver's own sentinel, which its read path produces for every offset-bearing `ZONED DATETIME`, so a write and a subsequent read agree. The instant is unchanged; only the location it is expressed in moves. A named location is left alone, because an IANA name is an identifier the server resolves and carries more than an offset does. **Without this, canonicalization would have widened a shipped defect**: an instant in a named zone passed `Coerce` untouched before, and now reaches it as offset-bearing text.

### Breaking on the generated-output surface

- **Removed: the `SerializedModel` and `SerializedModelEntry` declarations.** `adapter/gogen` emitted a shape-dependent pair — a string `var` on the single-source arm, a `map[string]string` plus an entry const on the multi-source arm — beside the uniform `SerializedSources()` / `SerializedEntry` pair v0.12.3 added on both. The two-shape emission is retired; the uniform pair is the only re-load surface, and its documented recipes are unchanged. This is what the Breaking tier's first bullet names, so it could not ride a patch, and it is why v0.12.3 shipped the additive accessor instead. **The consumer's migration already happened**: every reference to the removed names lives inside a `go generate`-rewritten file, and every hand-written call site already reads the pair. The cost is one `go generate` and zero hand edits.
- **Generated-output note: every generated file changes, and the single- and multi-source arms now emit the same shape.** The embedded sources move into one **unexported** package-level `map[string]string` for both source counts, which `SerializedSources` converts per call; `SerializedEntry` becomes a literal const on both arms rather than an alias on one. The one identifier added is unexported, so the consumer-visible surface does not grow — additive under that tier's first clause, alongside the removal above. `Marshal`'s round-trip self-check collapses onto the single arm it now needs. Consumers that byte-pin committed generated packages will see the diff and regenerate.
- **Generated-output note: `SerializedModel` and `SerializedModelEntry` stay in the reserved-name set** although nothing emits them. Freeing a name is not a no-op: a schema declaring a type of that name derives a schema-qualified Go name today and would derive the bare one after, which moves an emitted identifier for an existing input — the one thing this surface's Breaking tier forbids. The type mapping is unchanged.

### Additive

- **Additive: `instance.CanonicalValue(val any, c schema.Constraint) (any, error)`.** The canonicalization rule, exported for a caller rendering schema-typed values at a boundary this library does not own — a hand-built export, a direct-Cypher parameter map. Values reaching a graph through `instance.Validator` are already canonical. On error the returned value is the input unchanged, so a caller that heals what it can may ignore the error. It is the approved facade for the adapter layer, which imports no core internal package.
- **Additive: `diag.W_TIMESTAMP_LOSSY_FORMAT` (Warning).** Raised at schema load when `Timestamp["layout"]` declares a layout that cannot reproduce an instant — no zone, no fractional second, or neither. The declaration is **accepted**: a wall-clock layout is a legitimate domain choice, and rejecting it would break real schemas for a stylistic preference. Enumerating the loss silently is the opposite of predictable, so the author is told once, at the point of declaration, and the warning anchors on the format literal. The test for lossiness is a round trip through the layout, not a scan for directives, so a layout is judged by what it does. In-tree cost is nil: the only two declared layouts in the repository are a parser syntax fixture and a benchmark schema whose layout carries a zone.
- **Additive: `snapshot.WithValueConformance()` and `diag.W_SNAPSHOT_VALUE_NONCONFORMING` (Warning).** `Load` produces graph values yammm's own validator would reject, and until now nothing in the library could say so: the load path normalizes a `json.Number` and never consults the schema for a property value, `Verify` is structural by its own godoc, and the only `LoadOption` relaxed rather than tightened. The new option makes `Load` and `Verify` report a stored value its constraint cannot render. **Off by default**, so no behaviour changes and the walk costs nothing when nobody asks; **Warning severity**, so `Load` still returns the snapshot together with the findings — reporting a document is not refusing it. **Scope, stated honestly: it reports non-conforming values of the three canonicalizable kinds and nothing else.** Bounds, enums, patterns and invariants stay unchecked at load; it is not re-validation, and silence is not proof of validity.

## v0.13.1 under this policy

Patch tier: one bug fix in `adapter/neo4j`. No exported symbol is added, removed or re-signatured, and the `.ys` wire format is unchanged at `version: 3`. Permitted under the pre-1.0 patch rule's first clause — a bug fix that preserves the public API and the wire format.

- **Bug fix: `adapter/neo4j.Coerce` no longer lets the host's time zone reach the driver.** A `Timestamp` given as text was parsed with `time.Parse`, which returns `time.Local` — rather than an unnamed zone — when the parsed offset equals the local zone's offset at that instant. `Zone()` then reports a non-empty abbreviation, so v0.13.0's unnamed-zone rescue did not fire, and the driver sent `Location().String()` as a time-zone identifier: `"Local"` on a host with no `TZ` set, which the server refuses with `Illegal zone identifier`. - **Test note: the regression pin sets `time.Local` rather than reading it.** A fixture derived from the host's own zone cannot reproduce the case on a UTC host, because UTC-offset text parses to `time.UTC` and never to `time.Local` — so such a test passes vacuously on every CI runner, which is exactly where a regression would land. One DSL break, two Go-API removals, wire additions with no version bump, output-shape changes in every writer, one severity flip, and a set of behaviour tightenings; every item is a fidelity fix — the writers, the graph layer, the hash and the persisted format now hold what the schema states.

- **The reverse clause is removed.** `--> NAME (mult) Target / reverse_name (mult)` no longer parses as metadata; the grammar still recognizes the shape, and a schema carrying one draws `E_REVERSE_CLAUSE_REMOVED` (CategorySchema) naming this release. `yammm fmt` still formats such a file — formatting is not a validity gate; every load path rejects it.

- **`schema/testdata/hash_vectors.json` is recomputed** for algorithm 2 — the published cross-language reference vectors move with the algorithm.
- **The gogen `SchemaHash` constant moves for every schema** (regenerate with `go generate`).

### Output changes

- **`adapter/json` writers emit what their parsers accept**: an association is a `_target_<pk>`-keyed object with edge properties beside — one object for `(one)`, an array for `(many)` — and a composition is an array of child objects for every multiplicity. ### Breaking — Go API, `snapshot`

- **`snapshot.MinReadableVersion` is `4`** (was `3`), and it is now **derived** — `const MinReadableVersion = currentVersion` — rather than a second literal: this package reads only the version it writes, and two independent literals let a version bump widen the accept range to `[3, 4]` by accident, which is exactly what a prior test had pinned as two separate values. Widening the range is now a deliberate replacement of that expression. The wire change itself is the next section.
- **`snapshot.TypeRef.SchemaPath` is removed and `snapshot.TypeRef.Schema` is added**, so the type is `{Schema, Name string}`: the declaring schema's **name**, not its source path. `TypeRef.String()` and `MarshalText` render `schema#name` where they rendered `path#name`. Every `TypeRef` a schema-less read surface returns — `SnapshotInfo.Types`, `HeaderInfo.Types`, `HeaderInfo.UnknownTypes` — changes value accordingly. Rule (a): rdata reaches `TypeRef` only through `String()` in one rendering helper and reads no field, so it compiles; the rendering it prints changes (**consumer-visible**, owed to the hand-off).

### Breaking — the `.ys` wire: `version: 4`, and version 3 is refused

- **The types table is keyed by `{schema, name}` — the declaring schema's declared name and the type name — where version 3 keyed it by `{schema_path, name}`.** The ground is the library contradicting itself: `schema.StructuralHash` excludes source paths by design, so that embedded and disk loads of one schema text agree, while the version-3 table wrote `SourceID.String()` — for a file-backed source, the writer's absolute canonical path — and `typeByWireID` matched it exactly. Two snapshots of one schema text, one written from disk and one from embedded sources, therefore carried an **identical `schema_hash` and mutually unreadable type tables**; a document written on one machine failed to load against the same schema on another with one `E_SNAPSHOT_UNKNOWN_TYPE` per row and nothing to do but regenerate. A schema name is unique across an import closure — `Registry.Register` refuses a second schema with an existing name, and the loader registers every member — which is what makes it sufficient to denote a type, and it is the same rendering the neo4j label already composes from. **The row order moves with the key:** the table and the instances section that follows it are ordered by `(schema, name)`, where version 3 ordered by `TypeID.String()` — a path-derived order that assigned different row indices to the same identities loaded from two directories. `schema_source` in the header is unchanged: it is informational, read only by the Info surfaces, and decides nothing on load.
- **Asymmetric-reader semantics, per the policy's wire-format-incompatible clause:** the header's `version` increments 3 → 4; a v4 reader accepts **only** v4 — v1, v2 and v3 documents draw Error-severity `E_SNAPSHOT_UNSUPPORTED_VERSION` on every read surface (`Load`, `Verify`, `Info`, `HeaderOnly`, `HeaderOnlyRead`, `UpdateMetadata` and the `UpdateMetadataOrReMarshal` fallback); a v3 reader (v0.12.0 through v0.18.0) rejects a v4 document through its own unsupported-version path. **A v3 document is refused rather than migrated**, following v0.12.0's precedent: yammm supports one wire version at a time, and a transitional `[3, 4]` accept range was deliberately not taken. Every existing `.ys` must be regenerated from source data or read with an older binary. **Consumer-visible, measured:** rdata's five wire goldens under `pipelines/msrb/emma/testdata/wire/` carry `"version":3` and an `embedded://…` `schema_path` per row and fail their own drift gate, whose message asks for exactly this note; its `CheckSnapshotState` guard on `HeaderInfo.UnknownTypes` — written because it hit the path-keyed defect — now finds every row binding across paths, and `TestCheckSnapshotState_SchemaPathMismatch` fails at its own precondition. Retiring that guard is rdata's decision; the hand-off states what changed under it, together with the `.ys` regeneration on the volume.
- **`HeaderInfo.UnknownTypes` changes meaning as a consequence, with no signature moving.** It still returns the rows the closure does not declare, but moving a schema's files is no longer one of the cases: it now catches a schema that no longer declares a type the document names — a row removed or renamed, or a closure missing the declaring schema. Its godoc, which described the path-keyed defect as the method's purpose, is rewritten.

### Additive API surface

- **`graph.WithLogger(*slog.Logger) graph.Option` is restored.** The v0.12.0 notes above removed it while recording the intent that "the trace hook stays, defaulting to a no-op" — and what shipped was eleven `internal/trace` call sites in `graph/` that no caller could ever reach, because `WithLogger` had been their only constructor. The hook is now reachable again, on the same shape as the live `schema.WithLogger`: `Add`, `AddComposed` and `Check` open and close a traced operation, and edge resolution, forward references, duplicate primary keys and unresolved required associations log as they occur. With no logger every call returns immediately, so behaviour for a caller who passes none is unchanged. `graph.Option`, `graphConfig` and the `opts ...Option` variadics on `New` and `NewFromSnapshot` are unchanged in shape; what was missing was the constructor.
- **`diag.E_SNAPSHOT_INVALID_ROOT`** (Error) — an instances group names a type that cannot hold a root instance; see the `snapshot.Load` bullet below.
- **`diag.W_SNAPSHOT_VALUE_DROPPED`** (Warning) — the writer held a value the wire cannot carry at that position and did not write it; see the `snapshot.Marshal` bullet below. Both codes are in the plugin's diagnostics reference, which the `diag` parity test requires.
- **`(*location.Provenance).HasRawPath() bool`** — reports whether a raw path was recorded, which `RawPath()` alone cannot answer because a recorded empty string and no record both render as `""`. `WithRawPath` now records that a path was set. Added for the writer's provenance round trip below.
- **`snapshot.TypeRef.Schema`** — the field that replaces `SchemaPath`, counted by `gorelease` as an addition beside the removal above.

Module-root discovery adds thirteen declarations across two packages. All are additive: with no marker anywhere above an entry file, every load resolves the root exactly as it did before.

- **`schema.FindModuleRoot(dir string) (root string, found bool, err error)`** — walks the canonical ancestor chain for a `yammm.mod` marker, nearest ancestor winning, terminating at the filesystem root. A miss returns `""` and false rather than the start directory, so a caller can insert its own tier between discovery and its default; the editor does exactly that. Exported rather than private to `Load` because the LSP never calls `Load` — it loads through `LoadSourcesWithEntry` with the root as an argument — and a discovery mechanism reachable only from `Load` would give `yammm validate` one root and the editor another for the same file.
- **`schema.MalformedModuleRootError{Path string; Line int; Reason string}`** — matched with `errors.As`, on the precedent of the package's existing `RegistryError`, so the loader, the CLI and the editor render one message from its fields and no caller parses text.
- **`schema.ModuleRootMarker`** — the marker's file name, `yammm.mod`. The CLI help, the editor's file watcher and the guard tests reference it, so a rename would be a declaration change this tool reports.
- **`schema.ModuleRootIssue(err error) diag.Issue`** — maps either error kind to the diagnostic `Load` reports: a content violation to Error-severity `E_LOAD_MODULE_ROOT_MALFORMED` with both provenance details, anything else to Fatal `E_LOAD_IO_FAILURE`. Exported because the editor reports the same failure without going through `Load`, and one code built in two places is a code with two shapes.
- **`diag.E_LOAD_MODULE_ROOT_MALFORMED`** (Error) — a marker whose content violates the rule below. Error rather than Fatal: `HasFatal`'s godoc promises I/O or cancellation, and a marker is user content like a schema.
- **`diag.DetailKeyModuleRoot`, `diag.DetailKeyModuleRootOrigin`** — carried by every issue in the import-resolution family and by the malformed-marker issue.
- **`diag.ModuleRootExplicit`, `ModuleRootDiscovered`, `ModuleRootSynthetic`, `ModuleRootDefault`, `ModuleRootNone`** — the five values `DetailKeyModuleRootOrigin` takes. `default` names the entry schema's directory; `none` is a load that has no directory to default to — a `LoadString` source, a Builder-built schema, or an empty-root `LoadSourcesWithEntry` — and the two are deliberately distinct, because a load with no directory must not claim one.
- **`diag.IsImportResolutionCode(code string) bool`** — the mirror of `IsImportDeclarationCode`, true for `E_IMPORT_RESOLVE`, `E_IMPORT_CYCLE` and `E_PATH_ESCAPE`. The resolution family had no enumeration to key on, so a family-wide change had to be hand-rolled; the partition test now asserts that every `CategoryImport` code satisfies exactly one of the two predicates.

### Behaviour changes — `graph`

- **A non-OK `Graph.Add` or `Graph.AddComposed` leaves the graph unchanged.** Both now check the instance's whole structure — edge names and multiplicities, and every slot and child of the composition tree at any depth — before installing anything. Previously the instance installed first and three paths rejected afterwards, so a record the caller was told had failed was in the finalized snapshot: `BatchAssembler.Count()` under-reported against it, and retrying that record drew `E_DUPLICATE_PK`. What changes for a caller: a record carrying edge data under an undeclared name, a composed child of the wrong type, or a `(one)` composition holding several children is now refused entire rather than installed with the offending part dropped. The inline `(one)` overflow no longer records a `Duplicate` either — a `Duplicate` describes a child rejected under an *installed* parent, and there is no longer an installed parent to describe. `AddComposed`'s own duplicate records are unchanged.
- **A `(one)` composition carrying several children is refused by the validator.** `instance.Validator` accepted any array length for a composition, because a composition always arrives as an array and nothing about the shape settles multiplicity. It now draws `E_EDGE_SHAPE_MISMATCH`. This is the hole that made the install-ordering defect above reachable from ordinary JSON rather than from a bypass constructor alone.
- **The primary key is canonicalized where it enters the graph.** `Graph.Add`, `Graph.AddComposed` and `RebuildSnapshot` rewrite a `Timestamp`, `Date` or `UUID` primary key into the representation its constraint stores, once, at construction — and every position that addresses an instance moves with it: the instance index, an edge's endpoint keys, a duplicate's key, conflict and parent, and an unresolved record's source key. **What changes for a caller:** two spellings of one key value — `…T03:04:05+00:00` and `…T03:04:05Z`, or a UUID in two cases — are now **one instance**, so a second `Add` under the other spelling draws `E_DUPLICATE_PK` where the graph previously held two, and an edge written with one spelling resolves against a target written with the other. Only a key entering through the bypass constructor `instance.NewValidInstance` was ever non-canonical; a validated instance already carried the canonical form. `graph/canonical.go`'s type doc had stated the opposite rule on a ground that was false, and the first fix — canonicalizing at the snapshot writer — left the graph indexing by one spelling while its document carried another; it was replaced by this one and its writer-side machinery deleted.
- **`RebuildSnapshot` refuses a root of a type that cannot hold one.** An instances group, or a root duplicate record, keyed by an abstract type, a part type or a type declaring no primary key draws a Fatal `E_INTERNAL` naming the rule, as `validatePartsIdentity` already does for a zero identity: `Graph.Add` refuses all three, so admitting them here made the rebuild path the one way to assemble a graph the API cannot build, and the writer would then emit a document its own reader refuses. A **composed** duplicate legitimately names a part type and is untouched; `Relation` is what separates the two.
- **`E_CONTEXT_CANCELLED` from `Add` and `AddComposed` reaches `Snapshot.Diagnostics()`.** It was the only rejection those methods did not merge into the cumulative collector, so a half-built graph whose construction was cancelled reported `diag.OK()` construction diagnostics.
- **A composed child's type resolves across the whole import closure.** The graph resolved every type through one name-oriented lookup that reaches local and directly imported schemas only. That rule is right for a root, where it expresses *ownership* — a graph bound to a schema holds instances of the types that schema declares or directly imports — and right for `AddComposed`'s `parentType` argument, which is a name needing an alias. It is wrong for a composed child, whose type comes from a relation the schema already resolved and which arrived inside a parent the graph does own. The consequence was measured end to end: a schema where an imported type composes a part type from a further import loads clean and validates clean, and `Graph.Add` then dropped the child subtree silently on the inline path and disabled sibling duplicate-primary-key detection on the streamed one. Composed children now resolve through `schema.Schema.TypeByID`, which indexes the closure — the same call, and the same reason, `graph`'s snapshot import already used. A child whose identity is not in the closure at all still draws `E_GRAPH_TYPE_NOT_FOUND`. **The root path's direct-imports-only contract is unchanged**, including its transitive-import hint.
- **A composed child's primary key is checked against its own properties, on both paths.** `Graph.Add` applied that rule to a root and neither composed path applied it at all: a child of a keyed part type could carry an empty key, a key of the wrong arity, or a key disagreeing with its own key property. Both paths now draw `E_GRAPH_INVALID_PK`, and the rule subsumes a false positive it used to produce — two keyless children of a keyed part type both render `[]`, so the sibling scan reported `E_DUPLICATE_COMPOSED_PK` on a primary key neither child carried.
- **`BatchAssembler.AddValid(nil)` returns a per-record error instead of panicking.** `instance.Validator.ValidateForComposition` documents returning nil for each failed child, so the documented consumer loop crashed the process on the first failure. The rejection draws `E_INTERNAL` — the record is absent, not mis-keyed, and a consumer routing remediation off the code would otherwise be sent to inspect a primary key that does not exist. It reaches `Snapshot.Diagnostics()` like every other Add rejection, so a caller that discards per-record errors still has a record of the loss, and its contextual tag is the single token `"nil-instance (attempt #N)"` rather than an empty type name.
- **`BatchAssembler.Finalize` memoizes a completed outcome, and only a completed one.** Its godoc already promised that a second call returns the same result with no second `Check` pass; the body re-ran `Check` and re-took the snapshot on every call, so a second `Finalize` with a cancelled context turned a finished batch into a failed one. The first call's result and error are now stored and returned. **A `Check` that returned a Fatal — ctx already cancelled — is NOT stored:** cancellation is an abort rather than a result, the graph is unchanged, and a retry with a live context can still finalize. Since the assembler refuses further `Add` calls once `Finalize` has run, memoizing that outcome would leave a batch whose records are all present and valid with no recovery at all.
- **`RebuildSnapshot` returns a Snapshot with the ordering its accessors document.** It sorted edges and types and nothing else, so a snapshot assembled from parts violated the ordering `Snapshot.InstancesOf`, `Snapshot.Duplicates` and `Snapshot.Unresolved` promise, while one built through `Graph.Snapshot` honoured it — the same type, two constructors, two answers. A repeated identity in `SnapshotParts.Types` also made every instance of that type appear twice in `AllInstances` and twice in the persisted document. The invariant now lives in `newSnapshot`, which both constructors reach, so neither can get it wrong and a third cannot either. **Composed children are deliberately untouched:** `InstanceParts` documents that their order is the caller's, and a keyless child's position is its identity, so re-sorting them would move the address the writers assign. What changes for a `snapshot.Load` consumer: the per-type instance, duplicate and unresolved orderings become the documented ones where a writer had supplied another, and a duplicated type identity no longer double-counts.
- **`Snapshot.Duplicates` orders by the rejected instance's source position when nothing else separates two records.** `compareDuplicates` walked to the rejected instance's properties and stopped, so two rows of one file colliding with one instance — identical in every field and in their properties, differing only in where they came from — tied, and `slices.SortFunc` is not stable. A consumer pairing the Nth record with the Nth input row paired the wrong span. A loaded snapshot carries no provenance, so both sides render empty and the arm ties there, which is correct: two records with nothing left to tell apart are the same record.
- **`Graph.AddComposed` resolves the parent's type before looking for the parent.** An identity the schema closure does not contain — or the zero `TypeID` a caller reaches by forgetting to set one — now draws `E_GRAPH_TYPE_NOT_FOUND` rather than `E_GRAPH_PARENT_NOT_FOUND`, so a wrong type and a wrong key stay distinguishable and a caller does not retry keys forever against an identity that can never match.
- **`Add`'s error tag reads `"<TypeName> (attempt #N)"`, not `"<TypeName> (record #N)"`.** The number is the assembler-wide attempt ordinal across every goroutine, which cannot identify a caller's input row; the tag and `docs/API.md` no longer claim it can.
- **The `E_DUPLICATE_COMPOSED_PK` detail carries the child's primary key.** It was built with a nil child key, rendering a composed address `[["vin"],"SPARE"]` that `adapter/neo4j` assigned to nothing; an interim form carried the occupant's composed address instead. Both are gone with `FormatComposedKey`: on every path the `pk` detail is the duplicated child's own primary key — on `AddComposed`'s `(one)` path the **occupant's**, the child that actually attached, since the rejected child never does — and on a part type that declares no key the detail is **absent** rather than a stand-in. Whether a key exists is asked of the schema, not of the instance, because a test instance defaults to a key of its own.
- **`NewFromSnapshot` and the batch assembler's seeded form read an absent attestation as no support for the `Values` claim**, the same as importing a false one, since a document that claimed nothing cannot support a graph's claim.

### Behaviour changes — `adapter/neo4j`

- **The adapter's type walk is the import closure, and the emit set and the own set are one set by construction.** `labeledTypes` walked the entry schema's own types while `ShapeForSchema` walked the closure, so an imported type the schema writes nodes for got a label and node writes with **no constraint, no index, no ownership, and no visibility to the diff**. `ConstraintsForSchema` / `ConstraintsStructured`, `IndexesForSchema` / `IndexesStructured`, `DetectLabelCollisions` and `OwnedLabels` now all reach their types through one closure walk, and a label composes from the **declaring** member's name — an imported type keeps the label its own schema gives it, which is the label its nodes are written under. The invariant is stated on the walk so a later change cannot split the two sets: a label is owned exactly when it is desired, which is what keeps `DiffConstraints` and `DiffIndexes` from planning a DROP for a label the emitter still writes. **Consumer-visible, measured:** rdata's `linkage_emma` annotation-derived index set grows from 6 to 33 indexes, gaining every imported `census_tiger__*` and `msrb_emma__*` type, and its pinned-set test fails; the next migration creates the 27. A second consequence is stated as a question rather than a defect: rdata runs five schemas against one database and calls `OwnedLabels` per schema, so three schemas' owned sets now overlap on the labels they import — the desired sets derive from the same annotations, which argues they agree, and only the consumer's integration lane can confirm no spurious DROP. Unscoped mode widens too: `Adapter.Label` returns bare labels with an empty schema name, so the own set claims more bare labels.
- **`BatchNodeQueries` and `BatchEdgeQueries` require a `GraphShape` that `Adapter.ShapeForSchema` built from the snapshot's own schema, and refuse a nil shape, a hand-built one, or one built from another schema** with an error naming which. A shape the adapter did not build carries no key constraints, so merge keys reached the driver uncoerced while the same properties were coerced from the schema type — a `Date` primary key as a string in the MERGE key and a native date in the properties, matching nothing and **duplicating the node on every re-ingestion**. `GraphShape` carries an unexported `schemaID` only `ShapeForSchema` sets; the write path checks it against `Snapshot.Schema().SourceID()`. `NodeShape.keyConstraints`' documented degraded behaviour for a hand-built shape is retired with the test that pinned it. Rule (a): rdata builds every shape through `ShapeForSchema`.
- **A snapshot in which two type identities render one type name now writes**, each identity under its own label. `renderedNameCollision` refused it on the ground that the pair "would share one node shape and label", which has been false since v0.12.0 keyed `GraphShape.Types` by `schema.TypeID`; `ShapeForSchema` still refuses a closure whose **labels** collide, which is the real hazard, and its `E_NEO4J_LABEL_COLLISION` now names both identities.
- **`_composed_key` changes on every composed node, and finally.** The address is a flat JSON array of the owning root's **label**, the root's key values, then one segment per composition hop — `["shop__Order",["o1"],["SECTIONS",["s1"]],["NOTES",0]]`, with a `(one)` hop as `["REL"]` — where it was `[[parentKey],"REL",childKeyOrIndex]` rooted at the **immediate parent** and, below depth one, nesting the parent's whole address inside the child's. Three defects in the old form: it did not carry the root's type, so two root types sharing a key value and a relation name minted one address for children under one part label; it was rooted at the parent, which is wrong below depth one; and an interim form led with `schema.TypeID.String()`, which for a disk-loaded schema is the writer's **absolute filesystem path** — 175 characters at depth 1 against 48 now — putting the writing machine's directory layout on every part node. The adapter owns the format (`adapter/neo4j/composedkey.go`); the label is unique because `ShapeForSchema` refuses a colliding closure and portable because it carries no path. **A graph written by an earlier release needs re-ingestion of its composed subtrees**, which replace semantics make safe. **Consumer cost measured at rdata: a no-op** — it declares no composition or part type in any of its six schemas and never reads the property; it stays in the hand-off for a future consumer.
- **One temporal rule, stated once in `coerce.go`, with two arms.** *Timestamp:* a named location is kept only when the host's tz database resolves the name **and** the resolved offset agrees with the one the value carries; `time.Local`, an unnamed location, an unresolvable name **and a name whose offset disagrees** are all re-expressed in the value's own fixed offset. A value carrying `"MST"` at `+00:00` — which `time.Parse` mints from any layout with a zone-abbreviation token — previously went to the driver as a zone identifier the server re-resolved to `-07:00`, shifting the instant by seven hours. *Date:* all three arms — a `"2006-01-02"` string, a `time.Time` and a `dbtype.Date` — normalise to midnight UTC before conversion, because the driver derives the day number by an integer division that truncates toward zero and a pre-1970 instant carrying a time of day landed **a day late**: `1969-07-20T18:00:00Z` stored as `1969-07-21`, reproduced against a live server, while the same time of day in 2001 and the same date at midnight both stored correctly. **Values already written by an earlier release change for a pre-1970 `Date` with a clock**; re-ingestion of such rows is owed to the hand-off. **Consumer cost measured at rdata: not triggered** — its dates parse to exact midnight, so truncation equals floor. The second `RFC3339Nano` parse attempt is removed as unreachable: `time.RFC3339` already accepts fractional seconds.
- **One builder per diagnostic code.** `E_NEO4J_INVALID_IDENTIFIER` was constructed at six sites in three detail shapes, one of which put a relation name under the `type` key; `E_NEO4J_LABEL_COLLISION` at two sites with two detail sets. Each code now has one constructor: an invalid identifier carries `type` (always a type), `relation` (the declaring relation of an edge property, attributed there instead of under `type`), `property` and `label` as they apply; a label collision's message reads `types <id> and <id> all render label "…"` and its `type` detail carries the colliding **identities**, sorted, rather than display names. `DetectLabelCollisions` walks the closure (two **schema** names such as `geo-regions` and `geo_regions` sanitize alike and render one label for every same-named type they declare) and its message shape changes accordingly.
- **`yammm neo4j introspect` and `InferSchema` produce a human-edited starting point and say so.** A database holds labels and properties; type identity, association-versus-composition and import structure are not in it to recover, so the output opens with a comment stating it is not expected to load and marks every guess with a `TODO`: every edge is written as an association; a `List<Float>` may be a `Vector`; no index metadata is read; two labels rendering one type name are merged; an `import` is a **path** and is emitted as `import "./<name>" as <name> // TODO` where it was emitted as a bare schema name that no loader could resolve. Relations are sorted by type and target so two runs against an unchanged database produce the same text, and an edge whose target no type was inferred for says so. The CLI's `error: infer schema:` exit path is gone with the `error` return.
- **`WithScalarTypeConstraints(false)` suppresses every property-type constraint, list-shaped and scalar alike.** A `Vector[4]` and a `List<Float>` emit the same `IS :: LIST<FLOAT NOT NULL>` statement, and gating them apart meant the option suppressed the constraint for one declaration and not for an identical one. It is also the switch an operator on a Neo4j 5.0–5.8 server needs: property-type constraints do not exist below 5.9, the adapter has no version input, and nothing else turned them all off. **What changes:** a caller passing `false` no longer gets list-type constraints emitted. `WithRequiredOnlyTypeConstraints(true)` no longer skips the **`E_NEO4J_UNSUPPORTED_TYPE` rejection** with the emission — `docs/SPEC.md` promises a nested-collection property is rejected unconditionally, and an optional one escaped unreported.
- **`ConstraintsForSchema` returns nil where `ConstraintsStructured` returns nil**, so a caller need not know which entry point distinguishes an empty slice from a nil one. Constraint emission checks the context per type, as the write path does, and reports a cancellation as Fatal `E_CONTEXT_CANCELLED`.
- **`DiffConstraints` plans a `Drift` where it planned a `Create` the server refuses every run.** A plain **RANGE node index** over the same label and properties blocks a `UNIQUE` or `NODE KEY` constraint under any name — the server refuses a constraint whose backing index an equivalent index already provides — and only the same-name case was tested, so such a constraint reported as a `Create` that never took effect: a plan that never converges. The definition blocker admits only a node RANGE index, **measured on 5.26 Enterprise and 2026.05 Enterprise**: TEXT, POINT, FULLTEXT, VECTOR and every relationship index are accepted beside the constraint, and blocking on them reported permanent drift for the `@fulltext`-on-a-sole-primary-key shape `docs/SPEC.md` blesses. A backing index is excluded from the check because it exists for its own constraint; multi-label rows are skipped as the index side skips them.
- **`DiffIndexes.Excluded` counts each remote row once.** A backing index that serves a declaration was counted as excluded and then reported as the `Actual` of an `IndexMatch`. Owned non-declarable rows are held back and counted by what the comparison did with them: a `Match` consumes the exclusion, a block does not. A conservation test pins that every remote row lands in exactly one bucket.
- **`DropConstraintStatement` and `DropIndexStatement` backtick-quote every name.** They quoted only a name `ValidateIdentifier` objected to; the reserved-word table that validator depends on does not match the Neo4j documentation it cites, and quoting unconditionally removes this path's dependence on it. The Cypher is equivalent — `DROP INDEX \`idx_name\` IF EXISTS` where it was `DROP INDEX idx_name IF EXISTS` — **and the rendered string changes for every plain name. Consumer-visible, measured:** rdata asserts on the rendered statement in eleven `internal/migrate` tests, including a remediation statement embedded in an operator-facing error, and all eleven fail against this tree. Named here because it moved no declaration and came from a closed unit; it is owed to the hand-off.
- **The composition replace and create statements report what they matched.** Both are MATCH-anchored and were RETURN-free, so a parent the MATCH missed silently dropped a whole composed subtree with no error. Each now ends `RETURN count(*) AS matched_rows`, the always-on signal the relationship template already carries for the same reason; a consumer executing the phased slice can read a zero.
- **Write-path robustness, no signature moving:** a part carrying no properties at all no longer panics on a nil map when `_composed_key` is set; a composed parent whose type has no shape returns a named error instead of emitting an empty label into Cypher; `composedQueries` checks the context per root type; `ParamTypesForType(nil)` returns an empty `ParamTypes` like its sibling `ImmutableKeysFor`; `extractKeyProps` collects a coercion failure beside the missing and nil keys instead of returning on the first, so a caller with three bad keys learns of all three; `BatchEdgeQueries` coerces each distinct endpoint once rather than once per edge, so a hub node at the end of a thousand edges no longer pays the coercion chokepoint a thousand times; the chunks `BatchNodeQueries` and `BatchEdgeQueries` return are **clipped**, so a consumer appending a row to one query's `$rows` no longer overwrites the first row of the next; `composedKeyConstraints` returns two `Constraint` values with separate `Properties` slices. `IntrospectRelationshipsQueryFor` trims its filter as `Adapter.Label` trims a schema name, so an all-space filter discovers everything rather than building a prefix no label carries.
- **The server-backed integration harness fails instead of skipping when it cannot establish its subject.** `make test-integration` and the CI job exited 0 whether the matrix ran or not: a container that could not start, a failed driver, and a failed connectivity check each set a package-level skip, and a Docker or image-pull failure yielded a green job. The harness now returns 1 and says why; a capability the target genuinely lacks — an Enterprise-only constraint on a Community image — still skips. The suite also gains its first edge-merge tests against a real server, over the template production emits for every edge and the one rdata calls directly, including the silent wrong-prefix case that returns `matched_rows = 0` and no error. Outside `go test ./...` and the pre-commit gate by build tag; only an operator running the matrix sees the change.

### Behaviour changes — `snapshot`

- **`Load` refuses two structural impossibilities whatever the options say.** An instances group — or a root duplicate record — keyed by a type that cannot hold a root instance (abstract, a part type, or one declaring no primary key) draws Error-severity **`E_SNAPSHOT_INVALID_ROOT`** naming the rule; two root instances of one type at one primary key draw **`E_DUPLICATE_PK`**, the code `Graph.Add` uses for the same condition, because the wire has a diagnostics section for a rejected duplicate and two live instances at one address is not a shape it can carry. Previously both loaded: the second produced a snapshot whose own accessors disagreed — `RebuildSnapshot` appended every instance to the type's slice while its index kept only the last, so `InstancesOf` reported two and every edge on that key bound to one. An **empty** group is not a root claim and passes; a composed duplicate may name a part type. `snapshot/doc.go`'s contract sentence, which stated the reader's permissiveness as unconditional, now names the two exceptions. This library's own writer cannot produce either document, so the guard bites only on a foreign or hand-edited one.
- **`WithRevalidation` reports the type contradictions it promised to report.** The revalidation rebuild took every edge target's and composed child's type from the relation's declared target and never read the document's own row, so an edge whose wire `target_type` — or a composed child whose row — names a type the relation does not declare loaded **clean under the option documented as "the one that reports all of it"**. Both now draw `E_SNAPSHOT_TYPE_MISMATCH` at the option's severity, with `expected` and `got` rendered in the document's own `schema#name` vocabulary. The comparison is strict identity, matching the graph layer, which stages every edge with `rel.TargetID()` and admits no subtype widening. Two further guards on the same path: a validator `E_INTERNAL` passes through unretagged beside `E_CONTEXT_CANCELLED`, because retagging a Fatal about the **run** to the caller's chosen Warning made `Load` return `HasErrors() == false` on data the validator reported it could not finish checking; and the rebuild is bounded at the composed depth limit it follows, where it previously recursed past a depth the reader had already refused.
- **`Marshal` refuses two inputs it used to write, and can return Warnings on success.** A `WithIndent` value that is not whitespace draws Error-severity `E_SNAPSHOT_MALFORMED` and **no bytes**: the indent is written between JSON tokens, so `WithIndent("xx")` produced a document `json.Valid` rejects and `Load` refused, while `Marshal` returned `diag.OK()` and `WriteFile` put it on disk unreadable. A type whose declaring schema is outside the entry schema's import closure — reachable only through caller-assembled parts — draws `E_SNAPSHOT_UNKNOWN_TYPE` before a byte is written, because the version-4 table has no portable name for it and writing its source path would put a machine-local path into the field the re-key exists to keep free of them. And **a successful `Marshal` now returns Warning-severity `W_SNAPSHOT_VALUE_DROPPED`** for every value the snapshot held that the wire cannot carry: an unresolved record's target key or edge properties under a reason (`absent`, `empty`) that admits neither, and a target key `graph.ParseKey` cannot read. **A caller checking only `Result.Err()` sees none of them**, and the CLI's `yammm snapshot save` now renders them. **Consumer-visible, measured but silent:** rdata's main persist path checks `HasErrors()` after `Marshal` with no warnings branch, while five sibling sites have one; its tests pass because a discarded warning is silent. Owed to the hand-off as a fact, not a failure.
- **The writer invents nothing and contradicts nothing.** A snapshot carrying no attestation re-marshals with **no attestation block**, where it previously acquired `{"values":false,"associations":false}` — silence turned into a false negative claim by the second read (see the `Attestation` pointer above). A provenance whose recorded raw path is the empty string re-marshals as `""`, where the writer substituted the parsed path `"$"` and the `E_SNAPSHOT_PATH_FALLBACK` warning that had named the substitution was gone on the next read; `Provenance.HasRawPath` is what the writer now asks. A primary key is written in one spelling at every position that addresses the instance — its own key, an edge's `target_key`, a duplicate's `key`, `conflict` and `parent_key`, an unresolved record's `source_key` — because the graph now canonicalizes it at entry; a bypass-built UUID key previously emitted `3F2504E0-…` beside its own backing property's `3f2504e0-…`. And one identity is rendered one way on both halves: the writer's `E_SNAPSHOT_DEPTH_EXCEEDED` detail carries `schema#name` from the table row where it carried `path:name`, and the reader's `E_SNAPSHOT_UNKNOWN_TYPE` detail carries the full `TypeRef` where it carried a bare type name.
- **`Info`, `HeaderOnly`, `HeaderOnlyRead` and `UpdateMetadata` store at most 100 issues**, the default `Load` and `Verify` already had. They built a zero `loadConfig`, and a zero issue limit means unlimited, so no option could bound them; all five surfaces now start from one default. A caller needing every issue on a heavily malformed document reads it through `Load` with `WithIssueLimit(0)`.
- **`UpdateMetadataOrReMarshal`'s fallback keeps what the input stated and what its legs reported.** The `Load` + `Marshal` path carries the input document's indentation across (a pretty-printed document came back compact) and its `created_at` when the caller set none (a stamped document came back unstamped; a `created_at` the header states but RFC 3339 cannot parse is reported as `W_SNAPSHOT_VALUE_DROPPED` rather than dropped silently); the returned result carries **every warning the `Load` and `Marshal` legs produced** beside `W_UPDATE_METADATA_FALLBACK`, where a fresh collector had discarded them; and a nil schema **panics at entry on every call** rather than only on the first input the fast path refuses, which let a caller run for months and crash on the first malformed document. The fallback path is reachable only by a document this library's own writer did not produce — one that computes the integrity hash correctly over a byte shape `UpdateMetadata` refuses — which is exactly the population the helper exists to serve. `distinctFatalCodes` is renamed `distinctTriggeringCodes`, since it always included Error codes by design.
- **Two diagnostics name the right thing.** A document whose first key is not `yammm_snapshot` draws **one** `E_SNAPSHOT_MALFORMED` naming the observed key, where the decoder collected one and its caller wrapped a second. A duplicate record whose type reference is nil or out of range renders `(no types-table row)` and **omits the `type` detail**, where the four diagnostics after `requireRow` rendered the row-0 sentinel its own godoc promised never to bind to.

### Behaviour changes — module-root discovery

- **Every disk `Load` now resolves its module root over four tiers**: an explicit root (`WithModuleRoot`, `--module-root`, the LSP's `ModuleRoot` config), then the directory of the nearest ancestor holding a `yammm.mod` marker, then — in the editor only — the workspace folder containing the file, then the entry schema's own directory. Tiers 1 and 4 are what existed before; tier 2 is new and tier 3 is demoted beneath it. **With no marker anywhere above the entry file, behaviour is unchanged.** The marker beats the workspace folder because the marker is a file the author committed and the folder is wherever the editor happened to be opened.
- **The marker's content rule, and it is strict.** In this version a `yammm.mod` must be empty or hold only comment lines, where a comment line's first non-space byte is `#`. Any other content draws `E_LOAD_MODULE_ROOT_MALFORMED` and **fails the load**: a directory of that name, a dangling symlink of that name, a file over 64 KiB, a UTF-8 byte order mark, or any non-comment line. There is no silent fall-through, because a marker the author wrote and the loader ignored is the failure this mechanism exists to remove. Refusing content now reserves the whole format space — no file written under this release can be reinterpreted by a later one.
- **A discovered root widens the import sandbox, and that is the mechanism working.** Every import read goes through `os.OpenRoot(moduleRoot)`, so committing a `yammm.mod` at a repository root grants the loader read access to that whole subtree for imports — which is exactly what makes a repository-relative import resolve. Stated in `WithModuleRoot`'s godoc and in `docs/SPEC.md` rather than left for a reader to infer.
- **Under an explicit root no marker is read at all**, not even a malformed one. This is the single deliberate exception to the rule above, and it is what "explicit wins" means: a caller can always override a marker it did not put there.
- **The walk is canonical**, running on the symlink-resolved ancestor chain, so a marker reachable only through a symlinked spelling of the entry path is not consulted. `WithModuleRoot` is the escape for that case.
- **`Schema.ModuleRoot()` can return a value it could not return before** — a discovered root — which is observable behaviour that moves no declaration and that `gorelease` therefore cannot see.
- **Every diagnostic in the import-resolution family names the root and where it came from**, in structured details and in the message. `E_IMPORT_RESOLVE`, `E_PATH_ESCAPE` and `E_IMPORT_CYCLE` each gain `module_root` and `module_root_origin`, and each message gains one clause after a semicolon. The message carries it as well as the details because the text renderer prints no details — only `--format json` does — and the plugin hook reads the text output. The default clause names the marker as the remedy: *"module root <root>, defaulted to the entry schema's directory; a yammm.mod in an ancestor directory would widen resolution"* — the sentence that would have saved the consumer's CLI failure this release exists to fix.
- **One builder per code across both front doors.** `E_IMPORT_RESOLVE` was previously raised at six sites in three different detail shapes and `E_PATH_ESCAPE` omitted the alias its declaration had in hand. Every site in `schema/load.go` and `schema/builder.go` now builds through one unexported builder per code, so one code carries one shape: root and origin always, span, path and alias whenever a declaration exists.
- **The completer's key-absent branch is relabelled `E_INTERNAL`.** It raised `E_IMPORT_RESOLVE` while its own comment called it a loader bug, and neither front door can reach it — the loader binds or fails every alias before completion, and the Builder discards its resolution map whenever a path fails. Unreachable, so this is a relabel and not a behaviour change.
- **`Schema.ModuleRoot()` reports the synthetic root** for a load under `WithSyntheticRoot`, where it returned `""`. The option's own contract says the root "stands in for the module root, so module-style imports resolve under it", and an accessor returning `""` denied the root the loader used. A schema loaded this way is consequently a **supported** input to `gogen.Marshal`, whose embedded keys are relative to that root; the documented refusal is retired, with no new refusal and no companion accessor. `sourceKey` gains an explicit synthetic branch — a synthetic root is trimmed, not relativized, because `filepath.Rel` returned the right answer only through an accident of `filepath.Clean` on the scheme's double slash. **Consumer-visible**: rdata's runtime schemas load under `embedded://rdata`, so `ModuleRoot()` returns that where it returned `""`; no call site reads it.
- **`diagRootFor` in the CLI discovers on the failure path and refuses a scheme string.** A successful load inherits discovery through `Schema.ModuleRoot()`; a failed one has no schema, and without discovery its diagnostics relativized against a root the loader had not used. It now relativizes only against a filesystem-absolute root, so a synthetic root cannot reach the renderer.
- **The plugin hook stops passing `--module-root`.** `claude-plugin/hooks/validate-yammm.sh` ran `git rev-parse --show-toplevel` and passed the result. That walk guessed (one root for every schema set in a repository), failed silently outside a checkout, and widened the sandbox to the entire repository whenever it succeeded. It is deleted. **This regresses any repository that has not committed a `yammm.mod`**: a schema importing from the repository root draws a false `E_IMPORT_RESOLVE` on every edit until both the marker and a discovering binary are present. The safe transition order is marker, then the `yammm` binary on PATH, then the plugin — the marker is inert under `v0.18.0`, so it can be committed first at no cost.
- **The editor reports a malformed marker as a document diagnostic.** `Workspace.FindModuleRoot` returns `(string, error)` and consults the marker between its explicit config and its workspace-folder tier; the walk runs outside the workspace lock, once per debounced analysis, with no cache, because a cached miss would be the ignored marker again. A discovery failure builds its issue through `schema.ModuleRootIssue` and publishes through a new `Analyzer.SnapshotForResult`, which keeps `Analyze`'s contract exactly: an error only for a Fatal issue. Both are outside the Go-API promise (`lsp/` ships in lockstep with the tag) and are noted here rather than enumerated above. The VS Code extension watches `**/yammm.mod` beside `**/*.yammm`, and a marker event re-analyzes every open document.
- **The generated-output policy names the module root as an input.** gogen's embedded source keys and `SerializedEntry` are relative to the recorded root, so committing a marker above a schema changes those keys for an otherwise unchanged generation — an unchanged schema, unchanged options and unchanged version no longer fix the bytes by themselves. No code moves for this; the Generated-output surface section, the `adapter/gogen` package doc and `docs/API.md` state it. A generator that passes the root explicitly, as the consumer's does, sees no change.

### Behaviour changes — CLI

- **`yammm snapshot save` renders `Marshal`'s diagnostics.** It checked only the error, which is nil for a warnings-only result, so the `W_SNAPSHOT_VALUE_DROPPED` warnings written to stop the writer discarding values silently were themselves discarded one layer out.
- **`yammm neo4j introspect`** — see the `InferSchema` bullet: the output text changes, and the `error: infer schema:` exit path no longer exists.
